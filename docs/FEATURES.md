## AT commands

One command per line, case-insensitive. Out-of-range S register writes are rejected.

| Command | Meaning |
|---------|---------|
| AT | Attention, replies OK |
| ATD<name>, ATDT<name>, ATDP<name> | Dial a station by name (1 to 16 chars). A name that matches a forward, or the form `host:port`, is a Wi-Fi dial instead (see notes) |
| ATDV<name>[/<label>] | Voice call to a person by voice name (`ATDV REV`), or to one of their devices (`ATDV REV/PC`, split at the last `/`). Needs a voice app registered on this modem (the call goes out from the first registration's name and label), else ERROR; ERROR also during any call. Result codes: OK 0, CONNECT 1, RING 2, NO CARRIER 3, ERROR 4, BUSY 7, NO ANSWER 8, DECLINED 3 (a voice call declined, numbered like NO CARRIER).
Verbose CONNECT reads CONNECT <tier name> <air bps>/ARQ on radio (CONNECT <tier name> <air bps>/ARQ/LZ when the call compresses), CONNECT <tier name> <air bps>/VOICE on a voice call (never /ARQ or /LZ) and CONNECT WIFI TCP on a Wi-Fi call. RETRAIN lines are verbose only.

Notes:
- ATD strips one leading T or P, as Hayes does. To dial a name that starts with T or P, use the full prefix: ATDT TOM or ATDP PAT (ATDTOM would dial OM). A leading V means a voice call (ATDV), so a station whose name starts with V is dialed with ATDT: ATDT VINCE (ATD VINCE would be a voice call to INCE).
- Names compare case-insensitively.
- Escape: no data for S12 (1/50 s), then three S2 characters each less than S12 apart, then nothing for S12. Anything else is data. S12=0 turns the escape off.
- Data mode is 8-bit clean: a RETRAIN during data mode is held and printed after the OK of the escape (verbose mode). AT&V shows the current tier and the last 4 retrains. ATO prints CONNECT with the current tier. NO CARRIER prints right after the received data that fits in the host buffer, never later.
- A tier above a modem's S21 cap is never used: asked for one, the modem acks its cap instead, and the asker stops asking above it.
- ATH during a call prints NO CARRIER; with no call it prints OK. ATZ restores the saved settings (S registers, echo, verbose, hotspot, client network, forwards, publish; power-on defaults when nothing was loaded or saved) and hangs up silently.
- ATA with nothing ringing prints NO CARRIER; ATA in online command mode (a call is up) prints ERROR and the call stays up.
- A partial command line typed before a call connects (during RING or while dialing) is dropped at CONNECT.
- The station name is 1 to 16 printable ASCII characters without `:` (Config::new refuses anything else), so a dial like `BBS:1` is always host:port, never a radio name. Radio dial names containing `:` print ERROR.
- ATI prints three lines: LRA FLOWTRON DATAMASTER 3000 SERIAL MODEM - LFD3K-SM, then v0.5.0 r.420 BL4Z3B4ND ULTR4M0D3M, then S0N1C B00M R4D10 PR0 MAX.
- ATI gets a fourth line `LAST CRASH: <note>` only when the previous boot ended in a panic (the note is `file:line`, up to 64 printable characters). With no crash it prints three lines, as before.
- AT&V prints `RADIO OK` or `RADIO FAIL <code> ERR 0x<4 hex>` after the TX POWER line, once the firmware has brought the radio up. Code -1 is a BUSY timeout, -2 no chip, -3 bad config; the hex word is the chip's device errors.
- S30 is the only signed register: ATS30=-9 is accepted (a leading minus works for S30 only), ATS30? prints the signed value, anything outside -9 to 22 prints ERROR. AT&V shows `TX POWER S30=<n> dBm chip, about <n+12> dBm out`.
- Command lines are up to 128 bytes. `+` command arguments split on commas: an SSID, forward name or password may not contain a comma. SSID and password are taken as typed; the fields of AT+FWD are trimmed, so `AT+FWD=bbs, bbs.example.com, 23` works.
- ATDT order: a forward name (any case) first, then `host:port`, else a radio dial. Use `ATDT`, not bare `ATD`, for forward and host names that start with T, P or V (bare `ATD VAULT` would be a voice call to AULT).
- Wi-Fi dial (forward or host:port): `DIALING <target>` (verbose), then `CONNECT WIFI TCP` (numeric 1) when the platform's TCP connect succeeds, and data mode. No fake speed in the connect string. A refused or failed connect prints NO CARRIER; no connect within S7 seconds prints NO CARRIER and closes the attempt. When the far end closes, everything it sent is shown first (data mode), then NO CARRIER. The escape, ATO (prints CONNECT WIFI TCP again) and ATH (NO CARRIER, also while dialing) work as on a radio call; ATZ hangs up silently. ATDT or ATA while any call is up prints ERROR. A Wi-Fi dial also prints ERROR while the previous connection's close is still pending (the platform has not released that socket yet); try again a moment later.
- Wire mode: telnet (T) or raw (R), from the forward, or for host:port T on port 23 and R otherwise. In T mode the modem is a telnet client: it answers WILL ECHO, WILL SGA and WILL BINARY with DO, DO SGA and DO BINARY with WILL, DO NAWS with WILL NAWS plus an 80 x 25 window size, refuses everything else (DONT, WONT), never sends anything first, strips all commands and subnegotiations from what it receives (a subnegotiation is dropped whole up to IAC SE, however long; IAC IAC becomes one 0xFF; while the server does not send BINARY, CR NUL becomes CR), and sends 0xFF as IAC IAC. While our sending direction is not BINARY (the server has not said DO BINARY), CR LF goes out as CR LF and any other CR as CR NUL (RFC 854); a CR that ends the data so far is held until the next byte or 50 ms, then sent as CR NUL. Raw mode passes bytes untouched.
- Bridge (AT+PUB set): a radio call this modem answers is connected to the published forward only, never to any other host. The radio caller sees its normal CONNECT; what it sends before the wire is up is buffered (up to 2 KB, then the radio window holds it). The local host stays in command mode and sees `BRIDGE <name>` (verbose) once the wire connects, and NO CARRIER when the bridge ends. If the wire fails, does not connect within S7 seconds, or closes (after what it sent has reached the caller, at most S7 seconds), the radio call is hung up and the caller sees NO CARRIER. If the radio call drops, or the host types ATH or ATZ, the wire is closed. ATO during a bridge prints ERROR.
- One call at a time: a radio caller during a Wi-Fi call gets BUSY.
- `Modem::wire_state()`: 0 none, 1 dialing, 2 online, 3 bridging. `call_state()` shows a Wi-Fi call as dialing (1) or online (4, or 5 in online command mode). Lights during a Wi-Fi call: OH on from the dial, CD on once connected (and until NO CARRIER), SD and RD lit for 100 ms after wire traffic once connected, HS and EC off, no tier.
- AT&V adds `WIFI AP <ON|OFF> <ssid>  STA <ssid|OFF>`, `PWSHOW <0|1>` (1 while the generated hotspot password may be shown on the OLED), `PUB <name|NONE>` and `FWD <count>` after the RADIO line. When the firmware has reported the modem task's stack high-water mark (`lfd3k_set_stack_free`), AT&V ends that group with `STACK FREE <bytes>` (omitted until reported).
- AT&W sets a save-wanted flag the platform takes (`Modem::take_save_request`) and reads with `Modem::settings()`. `Modem::load_settings` applies a loaded copy at boot, including S0 auto-answer and S30. ATZ restores that copy.
- SimNet (AT+SIMNET): while it is on, AT&V prints `RADIO SIMNET <ip>` in place of the RADIO OK line (`RADIO SIMNET <ip> NET FAIL` when the firmware could not open the UDP socket; the modem stays on SimNet, `AT+SIMNET=<ip>` again retries and `AT+SIMNET=0` goes back to the SX1262), nothing is sent on RF (the SX1262 is in standby), `lfd3k_status_t.simnet` is 1 and the OLED labels the HS light `SI`. Datagrams go to `<ip>:4210` and only datagrams from `<ip>` are taken. A frame on a tier the modem is not listening on is not heard, as on the air. The idle scope shows the simulated channel (the RSSI the peer reports while a frame is received, else -110 dBm). The V4 tells the peer it hears it at +8 dB, -70 dBm. Steps for Rev: docs/simnet.md.
- `Modem::take_wifi_changed()` is true once after AT+WAP (any form that took effect), AT+WSTA (any form that took effect), ATZ or a settings load; the platform then re-reads `Modem::settings()` (a reference) and re-applies Wi-Fi. `note_ap_client_joined` asks for a save only when the saved copy still had the password shown, and the platform writes `Modem::saved_settings()` (never the live copy), so a join persists only that flag and other unsaved settings stay unsaved. The platform holds a Wi-Fi apply while any call is up (any wire state or radio call) and runs it after the call ends, and skips one that equals the config already applied (it keeps a hash, not the passwords).
- The hotspot password may be shown on the OLED (`Modem::show_ap_pass`) until a device joins (`note_ap_client_joined`), AT&W saved with a client network set, or the user sets a hotspot password of their own with `AT+WAP=<ssid>,<pass>` (only the generated first-boot password is shown); the flag is part of the saved blob.
- Secrets at rest: both the hotspot and the client password are stored unencrypted in the V4's flash (NVS and flash encryption are off). `AT+WSTA=0` then `AT&W` removes the client one from the saved settings, but NVS may keep the old bytes in flash until that page is reused.
- AT&V adds `HEAP MIN <bytes>` (the lowest free heap since boot, `lfd3k_set_heap_min`, reported once a second like STACK FREE, omitted until reported), right after STACK FREE.
- The wire socket has TCP keepalive (idle 30 s, interval 5 s, 4 probes), so a host that vanished ends the call with NO CARRIER.
- Discovery air manners: beacons, scans and scan answers go out only while no call exists (radio or Wi-Fi, including dialing and ringing) and never more than once per 10 s per modem. A beacon is due 300 s plus a random 0 to 60 s after start, after the last beacon, or after the last call ended; it waits while a scan collects answers or the channel is busy. A modem answers a ScanReq once, in a random slot of 0 to 10 times 250 ms; if the channel is busy at its slot it tries the next slot, and gives up after slot 10 or when it sent any discovery frame in the last 10 s. Random numbers come from an xorshift seeded with the station name and the start time.
- AT+SCAN waits for the 10 s spacing before sending (so a second scan right after the first starts up to 10 s later) and gives ERROR if its ScanReq cannot go out within 14 s. A call starting while a scan runs (ATDT, or a caller ringing) ends it with ERROR. Switching to HIDDEN before the ScanReq went out also ends it with ERROR (nothing is sent). ATZ ends it silently. Commands typed during the 5 s window run as usual.
- An AT+DIR? listing that is still printing ends silently when data mode starts (ATO or a CONNECT), so the data stream stays 8-bit clean.
- The SNR in a SCAN line is the worse of the two directions (how we heard the answer and how the other modem heard our ScanReq); the tier is the fastest one that SNR allows with the S20 margin.
- Directory: up to 32 entries, names compare case-insensitively, our own name is never added (also when two modems share a name or our own frames come back). Filled from beacons, scan answers, ScanReqs (in HIDDEN mode a ScanReq or an overheard scan answer only refreshes a name already known; beacons still add new names, which gives them no right to call a HIDDEN modem), a caller's CallReq to us (call id not 0), and the CallAck or Train of the station we dialed. When full, the least recently heard unpinned entry is replaced; pinned entries never are. The blob (for the platform's NVS) keeps every pinned entry and the 8 most recently heard others, with name, services and best tier; SNR and age start fresh after a boot (age shows `-` until heard again).
- `Modem::take_dir_save()` is true once after AT&W, or after a directory change once 60 s have passed since the last save (an entry added, replaced or removed, a pin, or new services or best tier; a beacon that only refreshes SNR asks for nothing). The firmware writes `Modem::directory().to_blob()` (through `lfd3k_take_dir_save`) to NVS key `dir` in the lfd3k namespace, held until no call is up like the settings, and at boot, after the settings (so an AT+NAME name is in force), hands the blob to `lfd3k_load_directory`, which parses it straight into the live directory (`Modem::load_directory_blob`, no second copy on the modem task stack). A missing or refused blob leaves the directory empty.
- HIDDEN mode: a CallReq to us from a name that is not pinned in the directory (heard entries do not count) is dropped before the call logic sees it, so nothing at all is sent (no RING on our side, no CallReject; the caller sees NO ANSWER). Pinned callers (AT+DIR=+NAME) ring and connect as usual. No beacons, no scan answers, and AT+SCAN is ERROR (a ScanReq carries our name). Dialing out (ATD or the menu) is allowed in HIDDEN: the owner chose to transmit, and the CallReq carries our name. Only AT+SCAN is refused.
- Beacon services byte: bit 0 auto-answer on (S0 above 0), bit 1 a forward is published, bit 2 the hotspot is on. A beacon also carries how many stations this modem heard in the last 15 minutes.
- AT&V adds `BEACON <mode>` and `DIR <entries>` after the FWD line. `MODE LFD3K-SM` (the running firmware mode) follows the DIR line.
- Voice frames: everything voice on the air is frame type 15; the first payload byte is a sub-type (0 voice beacon, 1 voice scan answer, 2 voice call request, 3 voice answer, 4 voice decline, 5 voice data, 6 listener; 7 and up reserved for channels). A type 15 frame with no sub-type byte or one this build does not know is dropped as a bad type, as every older build drops all of type 15, so nothing voice can be taken for data by an older build. The voice beacon and voice scan answer feed the directories; the voice call request, answer and decline go to the call logic (see voice calls below).
- Voice registrations: a voice app on a host link session (0 to 3) registers one voice name and device label (`Modem::voice_register`; the voice host protocol will call it); a second registration on the same session replaces the first. A registration lasts while the session sends frames (`Modem::voice_session_seen`) and is dropped 30 s after the last one (so a phone that briefly loses Wi-Fi keeps its name), or at once when the session leaves (`Modem::voice_unregister`). Registrations are never saved and are cleared at boot. Our own registrations never show in our voice directory.
- Voice beacon: with registrations and the privacy mode ON, a voice beacon (type 15 sub-type 0: our station name, then each registration's voice name and label) goes out at least 10 s after each normal beacon (the normal beacon itself never changes; it only gains services bit 3, `SVC_VOICE`, which older builds mask off) and soon after a new or changed registration (at the next free 10 s slot, normally within 15 s). It obeys every discovery air manner: no call, idle channel, not while a scan collects answers, one discovery frame per 10 s. With four 16 character names and 8 character labels it is 128 bytes, about 1.1 s on air at SF12 BW500.
- Voice scans: our ScanReq sets header flag bit 3 (`FLAG_VOICE`), which older builds ignore (they answer as before). A modem with registrations answers a flagged ScanReq with a voice scan answer (type 15 sub-type 1: the ScanResp fields, then each voice name and label) in place of its normal ScanResp, in the same random slot with the same listen before talk; without registrations, or to an unflagged ScanReq, it answers normally. ON and QUIET answer voice scans; HIDDEN answers nothing. A voice scan answer counts as a scan answer (SCAN line, the scan count, the station directory with its services) and adds its voice names. Up to 132 bytes, about 1.1 s at SF12, so an answer from the last slot ends at about 3.9 s; the scan window is 5 s for that (the limit for getting the ScanReq out stays 14 s).
- Voice directory: up to 16 voice devices (voice name and label, compared case-insensitively, and the station they were last heard through; the same device heard through another station moves there), filled from voice beacons and voice scan answers, never from frames that carry our own station name. Best tier from the SNR with the S20 margin (the worse of the two directions for a scan answer). In HIDDEN mode a voice scan answer only refreshes a device already known or records a device of a pinned voice name; voice beacons still add new ones, like beacons. When full, the least recently heard unpinned device is replaced; pinned ones never are. Renaming the modem (AT+NAME) drops unpinned devices heard through the new name. Pins are per voice name (`AT+DIR=+V:<name>`); only pinned voice names ring a HIDDEN modem.
- Directory blob v2 (`LFD2`, version 2): v1 plus, before the CRC, a voice name count (0 to 16) and one 17 byte record per pinned voice name (length, name zero padded). It is written only while a voice name is pinned; otherwise the blob is v1 (`LFD1`) byte for byte, so an older build still loads it. Once a voice name is pinned the saved blob is `LFD2`, which older builds refuse whole: going back to an older build loses the whole saved directory, station pins included, until it is rebuilt there. Both load; a v2 blob with a bad or duplicate (any case) voice name, nonzero padding or a count over 16 is refused whole. Pinning or unpinning a voice name counts as a directory change (saved after 60 s); hearing voice devices never does. At most 921 bytes, within the 1024 byte blob.
- AT&V adds `VOICE <registrations> <voice directory entries>` right after the MODE line.
- Voice calls (`core/src/voice/call.rs`): a call is placed to a person's voice name (ATDV, or the voice app through `Modem::voice_dial`), not to a station. The voice call request (type 15 sub-type 2: capability byte, the caller's station name, voice name and device label, the callee's voice name and device label, empty for any device; at most 76 bytes, header included) goes out on SF12 every 3 s until answered or S7 runs out, as a CallReq does. Old builds drop all of type 15, so they never ring for a voice call, also with S0 set. Data calls (CallReq, CallAck, Train, TierSet) are unchanged.
- Ringing: a modem rings (the voice app gets a ring for each matching registration; the terminal prints nothing) when one of its registrations has the called voice name (and the label, when one was given), except the caller's own device (our station name and that registration's label both equal the caller's). Station names never match a voice call. Ringing sends nothing. A modem already in a call, voice or data or Wi-Fi, ignores the request and sends nothing (no BUSY), so the person's other devices keep ringing. In HIDDEN mode only a caller whose voice name is pinned (AT+DIR=+V:<name>) rings; anyone else gets nothing (the caller sees NO ANSWER). S0 never answers a voice call, ATA does not either (a person picks up in the voice app), and ATH while a voice call rings stops the ring silently. Ringing ends when the requests stop, as for RING.
- Answer: the device picked up draws a random answer token and sends a voice answer (type 15 sub-type 3: the token, its station name and device label) and then a Train that is today's Train plus the 4 byte token. The caller binds to the first token it hears (from the answer, or from the Train if the answer was lost) and sends its TierSet with the token appended; TierAck, the probe and the connected call run as for data. A device whose token is not in the TierSet stops at once without sending anything more (`answered elsewhere` in the app); so does a device still ringing that hears another device's answer or the caller's TierSet. A later answer reaching a caller already bound gets no reply. A device that picked up sends its answer and Train at most twice (again 3 to 4 s later, or within 0.7 s when it hears the request again after its answer went out; the random part comes from its token, so two devices that picked up together do not repeat in step) and, with no TierSet carrying its token 6 s after the last one, stops silently (`answered elsewhere`), so a late pickup never keeps transmitting on SF12 over a live call. A caller bound by an answer whose Train never arrives within 9 s unbinds and sends its request again, so the devices ring again and someone can pick up (S7 still counts from the dial). A device that picked up stops silently S7 after picking up whatever it sent (also when its answer never found a quiet channel). An answer (with its Train) goes out only once the channel has been quiet for 150 to 1349 ms (drawn again for each send from the token and the send count); one still waiting to go out when the channel turns busy is taken back and does not count as a send. Another device that picked up the same call sends its Train the moment its answer ends, and a frame is only detected once its preamble is through, so an answer sent as soon as the channel looked free landed on that Train (found by the Task 9 test `two_pickups_one_winner`: the caller then waited 9 s, unbound and rang again, over and over). Two devices picking up in the same instant can still both be lost to a collision on both sends (1 of the 20 races in that test); both then hear answered elsewhere and the call rings again; two devices are never both connected.
- Decline: declining a ringing call (the voice app, `Modem::voice_decline`) sends the voice decline (type 15 sub-type 4) twice and stops ringing; repeats of that request do not ring this device again. The caller, if not yet bound to an answer, prints DECLINED and goes idle; other devices still ringing for that call hear it and stop.
- A voice call connects with `CONNECT <tier> <bps>/VOICE` and keeps the terminal in command mode (the call's bytes belong to the voice app, never the terminal or an AT+PUB bridge); it ends with NO CARRIER. Hanging up while the voice slots run sends the two Hangup frames in this end's own next sub-slots (a push to talk holder fills its slots, so a Hangup sent at once was often lost and the holder ended only after resync and S22), then the modem goes idle; if no sub-slot comes within three listen periods one Hangup goes out at once. The owning app gets Ended (and CallState idle) as soon as its Hangup is taken, not when the Hangups have gone (up to about 12.5 s at SF12); a Call or ATDV in that window is refused like any call while one is up (Error 4, ERROR), and works once the link is idle. ATH prints NO CARRIER at once, as before. Hanging up a device that picked up but was not yet chosen by the caller's TierSet sends nothing (a Hangup carries no token and would end the winner's call). Compression is negotiated as for data (the capability byte and the 4th Train byte) but never shown on the voice CONNECT.
- Voice beacon timing: a voice beacon sent soon after a registration (or when the privacy mode changes to ON with registrations here) stands in for the one after the next normal beacon when it went out less than half a beacon interval (150 s) before it; otherwise every normal beacon is followed by a voice beacon, as before.
- The radio queue slot grew from 40 to 132 bytes so the longest voice discovery frame fits (the voice call work needed it larger too). `Modem` 13,536 to 15,200 bytes (host build).
- Voice call timing, before the first voice (`core/src/voice/sched.rs`): from CONNECT a voice call runs on today's data timing (bursts, turns, ARQ), so the voice apps' scrambler handshake (their own bytes through the call's data stream) moves at full data speed. When an app says it is ready for voice (`Link::set_voice_ready`, sent by the voice host protocol's VoiceReady once the handshake and the trust decision are done), its later control bytes go out in small pieces (32 bytes, 24 at SF12). A Listener frame carries a chunk of at most the tier's size, except a longer chunk queued on a faster tier before a retrain (32 bytes from SF9, say, after a fade to SF12), which goes only where it cannot run into the other end's frame: in our own voice sub-slot, with the floor free, or where the listen period is several slots and the overrun fits the slot's spare time (SF12: 82 ms of 216). The answering modem then says "ready" in a listener frame (type 15 sub-type 6) about every 2 RTOs; the calling modem starts the voice slots once it is ready too and has heard that. Measured in the simulator with 400 bytes each way before both say ready: CONNECT to voice slots 131 ms at SF5, 371 ms at SF7, 1.2 s at SF9, 3.9 s at SF11, 7.3 s at SF12; CONNECT to the first voice frame heard 187 ms at SF5, 443 ms at SF7, 735 ms at SF8, 1.7 s at SF9, 5.4 s at SF11, 10.8 s at SF12.
- Voice call timing, slots: once both are ready the call runs on fixed slots of the talk plan's frame length instead of bursts and turns: the calling modem's sub-slot first, then the answering modem's, each 20 ms after the end of the frame before it. Every slot frame (voice data, type 15 sub-type 5, or a listener frame) carries the slot number and how late it started, so the answering modem keeps its slot clock on the caller's. Duplex tiers (SF5 to SF8): both ends send every slot, their voice frame or, when the person is quiet, a small listener frame. Push to talk tiers (SF9 to SF12): the floor holder sends every slot; the other end gets a listener sub-slot every 3 slots (1.2 s) at SF9 and SF10, every slot at SF11 and every second slot (4 s) at SF12, where one 2 s slot cannot hold a voice frame and a listener frame. Voice frames are never acked or resent. The modem holds up to two sealed voice frames from the app (one frame of slack for the send time moving within a slot); in push to talk, frames queued while the floor is not ours are dropped. Slot use per tier, voice sub-slot and listener sub-slot in ms with the share left free: SF5 46/28 in 120 ms (23 % free), SF6 73/34 (27 %), SF7 59/44 (41 %), SF8 74/62 (26 %), SF9 144/92 (56 %), SF10 246/154 (25 %), SF11 595/267 (13 %), SF12 1784/432 (0 % over a 4 s listen period).
- Voice call control bytes: every slot frame carries the data stream's ack; the data itself (the voice apps' control messages) rides in listener frames, one piece each. A side whose control bytes have waited 1 s since its last listener frame sends one in place of a voice frame, so control gets through during continuous talk (each piece costs one voice frame there).
- Talk plan by tier (`core/src/voice/plan.rs`): a tier is duplex only where both voice frames on air plus the scheduler's 20 ms slot guard after each leave at least 20 % of the frame free (`duplex_fits`, now checked on every tier, SF5 included, with the scheduler's real voice frame and guard instead of the data turn gap). SF5: Opus 10 kbps, 120 ms frames (170 bytes sealed; 12 kbps in 100 ms frames did not fit), duplex. SF6: Opus 8 kbps, 200 ms (220 sealed), duplex (Codec2 3200 before). SF7: Codec2 2400, 200 ms, duplex. SF8: Codec2 1300, 200 ms, duplex (push to talk with 400 ms frames before). SF9 and SF10: Codec2 1200, 400 ms, push to talk. SF11: 700C, 1 s, push to talk. SF12: 700C, 2 s, push to talk delayed. New codec id 8 (Opus 10 kbps); a 120 ms Opus frame is six 20 ms packets. The 20 ms guard assumes the 10 ms core tick and a quick turnaround; the firmware part must measure it on hardware.
- Push to talk floor: `Link::set_talk_key(down)` and `Link::floor()` (Mine, Theirs, Free). The floor starts free when the voice slots start; the first key down takes it; a key down while the other side holds it waits until they let go, then gets it. The calling modem decides (every frame carries the sender's talk key, the caller's frames carry who holds the floor), so both ends always agree. Floor and ready are the modems' own frames; the apps' control bytes stay opaque to the modem. In duplex the floor reads Free.
- Voice call timers: voice and listener frames count as signs of life and as SNR samples for retrain, keepalive and NO CARRIER. While the slots run the modem sends no keepalive PINGs, and the step-down and resync clocks count only slots in which the other side was due to send (a push to talk talker hears its listener only every few slots and is not lost). In push to talk a wall clock cap rides on top (no frame of any kind heard, L = listen period: keepalive PINGs from 3 L, a step down from 5 L with two unanswered, a resync from 7 L, never sooner whatever S22 says, so a short S22 cannot turn ordinary loss into PINGs or a step down): PING / step down / resync from 3.6 / 6.0 / 8.4 s at SF9 and SF10, 3 / 5 / 7 s at SF11, 12 s / none / 28 s at SF12. S22 ends a call only from a resync: on SF9 to SF11 it counts from the resync, so the resync always comes first; on SF12 (already the resync tier) it counts from the last frame heard, so with S22 under 28 s (the default 20 s) the call ends with NO CARRIER at 28 s of silence instead of resyncing (task 7; before, the steps were capped at 40, 50 and 60 % of S22). Duplex tiers need no cap (every slot counts): resync after 8 RTOs, 1.5 s at SF5 to 4.3 s at SF8. Measured in task 6 (with the S22 caps): a fade under the floor resyncs after 7.2 s at SF9, 8 s at SF10, 6 s at SF11, 10 s at SF12. A tier change switches the codec and slot layout at the next slot boundary and prints RETRAIN as before. In the simulator 300 s of push to talk at SF9 and SF12 with 10 % frame loss changes nothing; a fade under the tier's floor still retrains (through a resync to SF12, as data calls do).
- `Modem` 15,344 to 16,160 bytes (host build): the scheduler, a two-frame voice send queue and a one-frame receive buffer.
- Settings blob v2 is 900 bytes (the beacon mode byte at 897, CRC at 898). A v1 blob (899 bytes) from phase 3 still loads, with the mode ON, and the next save writes v2.
- Settings blob v3 is 917 bytes: the station name (length byte, 16 bytes) follows the beacon byte at 898, CRC at 915. Length 0 means the firmware's name. v2 (900 bytes) and v1 (899) blobs still load with no stored name, and the next save writes v3. Renaming drops our new name from the directory (never our own name).
- Compression (S31): the caller adds one capability byte to its CallReq when its S31 is 1 (no byte means no compression, the form older builds send; an older build cannot take a CallReq that has the byte, so set S31=0 to call one). The answerer agrees when its own S31 is 1 too and says so with the same byte on its CallAck and as a 4th byte of its Train (sent only to a caller that offered). The caller takes the answer from the Train, which it cannot connect without, so both ends always agree. The call compresses when both offered; CONNECT then ends in `/ARQ/LZ` (also on ATO). S31 is read when the call starts; changing it during a call takes effect on the next call. Each 200 byte ARQ chunk is compressed on its own when its Data frame is built (a resend compresses the same chunk to the same bytes) and goes out compressed only when that saves at least 8 bytes. A received compressed frame that does not decode is dropped without an ack, so it is sent again. Wi-Fi calls are not compressed.
- AT&V ends with `LZ ON|OFF RATIO <n.n>` for the current or last radio call: Data payload bytes before compression over Data payload bytes on the air, both directions and resends included, one decimal, `1.0` when nothing was sent. The S register line now ends with `S31=<n>`.
- S31 is stored in the settings blob as flags bit 4, inverted (set means S31 = 0), so the blob stays v2 at 900 bytes and every saved v2 blob loads with compression on.
- Setup menu (AT+MENU, core/src/menu): an 80x24 screen for a CP437 terminal (SyncTERM). Keys: arrows (`ESC [ A..D` or `ESC O A..D`), Enter (CR, LF or CR LF), Esc (an ESC with nothing after it for 150 ms), Backspace (BS or DEL), Tab (next row), and the first letter of an item (jumps to it, and on the main menu opens it when no other item starts with that letter). Other escape sequences are swallowed whole. While the menu is open every host byte is a menu key: the AT parser and the `+++` escape see nothing.
- Menu screens: Directory and Scan (name, best tier, age, SNR, RSSI, pin, offers; Enter leaves the menu and dials the entry exactly like `ATDT <name>`, S scans like AT+SCAN with the answers landing in the list, P pins, A adds a name and pins it, D deletes after a Y or N); Link Status (call state, tier and ladder, last SNR, RSSI and frame tier, retrains, throughput in call data bytes per second both ways (bytes the host or a bridge moved in or out of the call, so 0 while the menu holds a plain call), compression and its ratio, the Wi-Fi line; updated once a second); Settings (station name, edited in a text box that runs AT+NAME, empty for the firmware's name; privacy mode; S30; S21; S0; S31; S32); Forwards (8 slots; A adds, Enter or E edits host, port and mode, D deletes after a Y or N, P publishes or unpublishes); Wi-Fi (hotspot on or off, name, password; client network and password, forget; the live status line); About (banner, version, release name, tagline, radio status, stack and heap, last crash, directory count, privacy mode); Save settings (AT&W); Exit menu.
- Menu edits compose the AT line the user would type (for example `ATS30=7`, `AT+BEACON=QUIET`, `AT+WSTA=<name>,<password>`, `AT+FWD=<name>,<host>,<port>,<T|R>`, `AT+DIR=+<name>`) and run it through the AT parser and dispatch, so they take exactly what the AT commands take; fields are also checked as they are typed in with the same rules. A changed value is live at once (like the AT command) and stays after a reboot only after Save settings. Directory pins and deletes are immediate, like AT+DIR. Passwords show as `********` always, typing one shows one `*` per character, and the typed text and the composed line are wiped after use.
- Leaving the menu: Esc on the main menu, or Exit menu. With unsaved changes (the live settings differ from the saved profile; the status line shows UNSAVED) it asks: Y or Esc discards (back to the saved profile, like ATZ but without hanging up, so it also drops AT changes made before the menu that were never saved), S saves and leaves, N stays. So Esc always gets out: Esc closes a text box, Esc goes back to the main menu, Esc leaves, Esc discards. Leaving clears the screen (colors reset, cursor shown) and prints OK; a NO CARRIER that came while the menu was open is printed first, and RING after OK when a caller still rings (ATA then answers). A scan still running ends silently.
- While the menu is open nothing else reaches the terminal: result codes and info lines are held back, RING shows in the status line, and call data stays in the call (the window then holds the far end, as in online command mode). Mid-call (`+++` then AT+MENU), leaving returns to online command mode and ATO goes back to the call. A call that connects while the menu is open (auto-answer with S0) closes the menu first, then CONNECT prints as usual.
- Menu drawing: rows are composed from the live state, hashed, and only rows whose hash changed are sent (after a key, an event, or once a second). A row goes into the host output whole, and only while 96 bytes stay free behind it; otherwise it waits for the next tick or for the host to read, so a slow terminal only slows the redraw and the host output ring stays 1 KB. The bottom right cell is never written (the status line ends with an erase to end of line), so no terminal scrolls.
- Boot to menu (S32 = 1, saved by AT&W): the first host bytes after boot open the menu and are dropped, except a first input that begins with `AT+VOICE` and CR, which starts the voice host protocol (see that section). ATZ does not open it. S32 is stored in the settings blob as flags bit 5 (set means 1), so every older blob loads with S32 = 0. AT&V's S register line now ends with `S32=<n>`.
- Menu preview: `cargo run -p lfd3k-sim --example menu_preview -- <dir>` writes the sessions as `.ans` files, and `py -3.14 tools/menu_preview.py <dir>` replays them on a strict 80x24 terminal, checks that a normal session, one drained 7 bytes per millisecond and a fresh full paint end on the same screen, and draws the PNGs in docs/phase4-bench/menu.

## Voice host protocol

Version 1, between a voice app (the PC app, the phone app) and its modem (`core/src/voice/host.rs`). The modem never sees keys or audio: voice and control bytes are opaque to it.

### Links and sessions

- Up to 4 sessions per modem. Session 0 is the modem's host stream (USB, or the V3's UART): the app sends `AT+VOICE` and CR, reads the echo and the `OK` (verbose `\r\nOK\r\n`), and from then on the stream carries frames both ways. Sessions 1 to 3 are the platform's (TCP in the firmware plan): `Modem::voice_open(session, now_ms)` opens one, `voice_input(session, bytes, radio, now_ms)` hands it the app's bytes (returns how many it took; offer the rest again later), `voice_output(session, buf)` fills `buf` with bytes for the app (whole frames, possibly split across calls; call it every tick), `voice_close(session, now_ms)` when the socket closes. `voice_open(0)` is refused: session 0 opens only with AT+VOICE, and the platform's `host_input` and `host_output` carry it.
- Begin with a single 0x00 byte, then the first frame (the 0x00 ends anything partial; one LF right after the AT+VOICE line's CR is skipped too).
- A session closes on Leave, on `voice_close`, or after 5 s (`VOICE_HEARTBEAT_MS`) with no good frame from the app: send Heartbeat (or any frame) at least every 2 s. On close a call the session owns is hung up at once. Its registration then lives 30 s more (`VOICE_GRACE_MS`, so a phone that drops Wi-Fi for a moment keeps its name), except after Leave, which drops it at once. Session 0 goes back to AT commands: the next byte is AT text again, and `NO CARRIER` comes first when it owned a connected call (not one still dialing or training, which is dropped silently). After Leave the modem sends no more frames on that session.
- With S32 = 1 (boot to menu) a first host input that begins with `AT+VOICE` (any case, nothing before it) followed by CR, in one write, starts framed mode as usual instead of opening the menu; any other first input (a leading CR or LF included) still opens the menu.
- While session 0 is framed nothing of the terminal reaches the host stream (no echo, RING, CONNECT, RETRAIN, NO CARRIER), and a data caller is turned away (its ring is rejected, the caller sees BUSY; if S0 had already answered, the call is hung up and the caller sees NO CARRIER). AT+VOICE is ERROR in online command mode, during a data or Wi-Fi call (also dialing or ringing), and from an AtLine; a voice call already ringing or up may stay.

### Framing

- Every frame is COBS encoded (blocks of up to 254 data bytes, the 0xFF block rule) and followed by one 0x00 byte. Decoded, a frame is one type byte and its payload, at most 260 bytes in all.
- A frame that does not decode (a block cut short by the 0x00, longer than 260 bytes, or empty) is dropped silently; the next 0x00 starts a fresh frame. A frame that decodes but has an unknown type or a payload of the wrong shape is answered with Error.
- Integers are little endian (u16, i16, u32). A `str` is a length byte, then that many bytes (names and labels are printable ASCII). A signed value shown as "none" is -32768 (0x8000).

### Who gets what

- The session that placed a call (Call, or ATDV from the terminal: the first registered session), or the session that answered it, owns it. Only the owner gets CallState, Floor, VoiceIn, ControlIn and the end of call message, and only the owner may Hangup, VoiceOut, ControlOut, TalkKey and VoiceReady.
- A ringing call goes to every open session whose registration it rings (voice name, and label when the caller gave one; never the caller's own device), as Ring every 3 s. When one of them answers or declines, the others get AnsweredElsewhere or Declined. When the ring stops with no pickup here, every rung session gets AnsweredElsewhere (another device picked up), Declined (another device declined) or RingEnded (the caller gave up or hung up, or S7 ran out).
- Each session's frames go out one at a time; the next is built when the last has gone, in this order: HelloAck, Error, Ring, the end messages (AnsweredElsewhere, Declined, NoAnswer, RingEnded, Ended), CallState, Floor, ControlIn, VoiceIn, AtReply, DirEntry or DirEnd, AirEvent, Scope. Nothing waits in a queue that can fill up, so an end or a state change is never stuck behind voice; a session that does not read loses only VoiceIn frames (the modem keeps the last voice frame heard), AirEvents (the modem keeps the newest 8) and Scope samples (the newest 8 go in the next Scope).
- Scope and AirEvent go to every open session, call or no call, last in the order above, so they never hold back anything else. The platform feeds the scope with `Modem::scope_sample(rssi_dbm, tx, now_ms)` every 50 ms: the RSSI it reads (GetRssiInst on the SX1262, the same samples as the OLED idle scope; `SimNetRadio::rx_rssi` on SimNet, the RSSI of a frame being received or the -110 dBm floor) and whether it was taken while transmitting (the firmware's trace gives 0 dBm then). The modem keeps the newest 16; every 5 samples (about 250 ms) each open session is due a Scope with the samples it has not had (at most the newest 8; older ones are dropped, never queued). Every frame the modem starts sending, and every frame it finishes receiving (its own or anyone's), is an AirEvent; each session reads them at its own pace from a ring of the newest 8, and one that falls further behind loses the oldest. A session that opens starts with the next sample and the next frame.

### App to modem

| Type | Name | Payload | What the modem does |
|---|---|---|---|
| 0x01 | Hello | version u8 (1) | Answers HelloAck. Send it first |
| 0x02 | Register | name str, label str | Registers this session's voice name (1 to 16 printable ASCII, no `:`) and device label (1 to 8 printable ASCII, no `:` or `/`); a second Register replaces the first. Silent on success; Error 4 for a bad name or label |
| 0x03 | Unregister | none | Drops this session's registration at once |
| 0x04 | Call | name str, label str (empty: any device) | Places a voice call from this session's registration to that voice name; this session owns it and gets CallState. Error 4 with no registration on this session, a call of any kind up, or a bad name or label |
| 0x05 | Answer | none | Picks up the call that rang this session; this session owns it, and its device label goes in the voice answer. Error 3 if this session was not rung, Error 4 when the ring is already over |
| 0x06 | Decline | none | Declines the call ringing this session (the caller sees DECLINED; this device stops ringing and is not rung again by that call). Error 3 when nothing rings this session |
| 0x07 | Hangup | none | Owner: hangs up the call or stops dialing; Ended follows. Error 3 otherwise |
| 0x08 | VoiceOut | sealed voice frame, 1 to 246 bytes (at most CallState's max_sealed) | Owner, connected, and only on a duplex tier, or while the floor is Mine and the TalkKey is down (a VoiceOut after TalkKey 0 is dropped; the frames queued before it still go out): queued for the next voice slot (the modem holds 2 in duplex, 6 in push to talk; one more is refused). Anything else is dropped silently (never an Error for voice) |
| 0x09 | ControlOut | bytes, 1 to 259 | Owner, connected: into the call's reliable stream (ARQ, in order); the far app gets them as ControlIn. If the stream cannot take them all at once the rest is held and the modem takes no more bytes from this session until it has (`voice_input` returns less than offered). While bytes are held, later frames from this session are still taken and acted on (Hangup, Decline, Leave, TalkKey, Heartbeat, VoiceOut and every other type) as soon as each whole frame has been offered; only a later ControlOut waits behind the held bytes (the stream keeps its order), and with it everything after it. A session never times out while it holds bytes (the 5 s clock restarts once they are taken). Once the voice slots run, control bytes move in small listener pieces (24 bytes every 4 s at SF12), so keep control messages small after VoiceReady. Error 3 with no connected call |
| 0x0A | TalkKey | down u8 (1 down, 0 up) | Owner: the push to talk key. Error 3 otherwise |
| 0x0B | Heartbeat | none | Keeps the session (and its registration) alive |
| 0x0C | Leave | none | Closes the session and drops its registration at once; a call it owns is hung up. Session 0 goes back to AT commands |
| 0x0D | DirList | none | DirEntry for every directory entry, then DirEnd |
| 0x0E | VoiceReady | none | Owner, connected: the scrambler handshake and the trust check are done; the voice slots start once both apps have said it (CallState flags bit 0). Error 3 otherwise |
| 0x0F | AtLine | one AT line, up to 128 bytes, no CR needed | Runs it (see AtLine below) |

### Modem to app

| Type | Name | Payload | When |
|---|---|---|---|
| 0x81 | HelloAck | version u8, station str | Answer to Hello: the modem's protocol version and station name |
| 0x82 | Ring | station str, name str, label str | A call rings this session's registration: the caller's modem, voice name and device label. Every 3 s while it rings |
| 0x83 | CallState | state u8, flags u8, sf u8, codec u8, mode u8, frame_ms u16, max_sealed u8, snr_x4 i16, rssi i16, peer station str, peer name str, peer label str | Owner, see below |
| 0x84 | AnsweredElsewhere | none | A ringing session: another device picked up. The owner after Answer: the caller chose another device that picked up at the same time (our call is over) |
| 0x85 | Declined | none | The owner of a call placed: it was declined. A ringing session: another device declined it |
| 0x86 | NoAnswer | none | The owner of a call placed: nobody answered within S7 |
| 0x87 | Ended | none | The owner: the call is over (either side hung up, the link was lost past S22, or this app hung up) |
| 0x88 | VoiceIn | sealed voice frame | The owner: a voice frame heard |
| 0x89 | ControlIn | bytes, 1 to 255 | The owner: the far app's ControlOut bytes, in order, as fast as this session reads them |
| 0x8A | DirEntry | kind u8, flags u8, sf u8, age_s u32, snr_x4 i16, rssi i16, services u8, name str, label str, via str | One directory entry, see below |
| 0x8B | DirEnd | count u8 | End of the DirList: entries sent |
| 0x8C | Floor | floor u8 (0 free, 1 mine, 2 theirs) | The owner, when the push to talk floor changes (free in duplex and before the voice slots run) |
| 0x8D | Error | type u8 (the message refused), code u8 | See the codes below |
| 0x8E | AtReply | flags u8 (bit 0: final), text | AtLine output, see below |
| 0x8F | RingEnded | none | A ringing session: the ring stopped with no pickup or decline anywhere this modem heard (the caller gave up or hung up, or S7 ran out) |
| 0x90 | Scope | t_ms u32, step_ms u8, n u8, tx_mask u8, n x dbm i8 | Every open session, about every 250 ms: channel samples, see below |
| 0x91 | AirEvent | flags u8, sf u8, type u8, sub u8, len u8, start_ms u32, air_ms u16, rssi i16, snr_x4 i16 | Every open session: one per frame sent or heard, see below |

CallState:
- state: 0 idle (sent once after the end message), 1 dialing (requests going out, or an answer heard and its Train awaited), 3 training, 4 connected, 5 resync (the link was lost: both ends on SF12 getting it back; S22 later the call ends). 2 (ringing) is never sent: a ring is Ring.
- flags: bit 0 the voice slots run (both apps said VoiceReady), bit 1 this modem placed the call.
- sf: the call's tier as its spreading factor, 5 to 12; set from the probe on (state 3 while probing, then connected and resync), 0 before that (dialing, and training before the probe starts).
- codec, mode, frame_ms, max_sealed: the talk plan of the tier (`core/src/voice/plan.rs`). codec 0 none yet, 1 Opus 12 kbps, 2 Opus 8 kbps, 3 Codec2 3200, 4 Codec2 2400, 5 Codec2 1300, 6 Codec2 1200, 7 Codec2 700C, 8 Opus 10 kbps; mode 0 none yet, 1 duplex, 2 push to talk, 3 push to talk delayed; frame_ms the voice frame length; max_sealed the most bytes one VoiceOut may carry on this tier. After a retrain the new plan takes effect on the air at the next slot boundary: switch codecs when CallState shows it.
- snr_x4 and rssi: the last frame of this call heard (SNR in dB x4, RSSI in dBm); none before one.
- peer station, name, label: on a call placed, the voice name dialed and, once a device answered, its device label and modem station (until then the label dialed, or empty, and an empty station); on a call answered, the caller's.
- Sent when the call starts (Call or Answer), on every change of state, flags, sf or talk plan, once a second while connected (fresh SNR and RSSI), and once with state 0 after the end message.

DirEntry: voice devices first (up to 16), then stations (up to 32); this modem's own registrations never appear.
- kind: 0 station, 1 voice device.
- flags: bit 0 pinned, bit 1 heard since boot.
- sf: best tier as a spreading factor (0 none).
- age_s: seconds since last heard, as of the DirList; 0xFFFFFFFF when not heard since boot.
- snr_x4, rssi: a station's last frame; none for a voice device.
- services: a station's beacon services (bit 0 auto-answer, bit 1 a forward published, bit 2 hotspot on; the directory keeps only bits 0 to 2, so a station's voice names bit is not passed on); 0 for a voice device.
- name: the station name, or the voice name. label: the device label (empty for a station, and for a pinned voice name not heard yet). via: for a voice device the station it was heard through (empty until heard); empty for a station.

Scope (16 bytes at most: the type, 7 bytes, up to 8 samples):
- t_ms: the modem's clock (ms) when the last sample of this frame was taken; step_ms: the time between the last two samples the modem was given (50; 0 before a second sample, 255 for 255 ms or more). The samples are oldest first, each step_ms before the next.
- n: samples in this frame, 1 to 8 (the ones this session has not had, the newest 8 when it missed more).
- tx_mask: bit k set when sample k was taken while the modem was transmitting.
- dbm: one i8 per sample, the RSSI in dBm (-128 to 127; a transmit sample carries what the platform gave, 0 from the firmware's trace and the PC app).

AirEvent (16 bytes: the type and 15):
- flags: bit 0 set for a frame heard (received), clear for a frame sent. Other bits 0.
- sf: the frame's tier as its spreading factor (5 to 12).
- type: the header frame type (1 to 15, `frame.rs`); 0 for a frame that is not ours (another system's traffic) or shorter than a header.
- sub: the type 15 sub-type (0 voice beacon to 6 listener, `voice/frames.rs`); 0xFF for every other type.
- len: bytes on the air (header included).
- start_ms: the modem's clock (ms) when the frame started on the air: for a frame sent, when the modem handed it to the radio; for a frame heard, when it finished less its airtime.
- air_ms: its airtime from `Tier::airtime_us` (BW 500 kHz, CR 4/5), rounded to the nearest ms.
- rssi, snr_x4: what a frame heard was heard at (dBm, dB x4); none for a frame sent.

Error codes: 1 unknown type; 2 bad payload (wrong length, a malformed string); 3 no call (not rung here, not the owner, or not connected); 4 refused (a bad name or label, no registration on this session, a call already up, the ring already over); 5 busy (another AtLine, from any session, has not had its final AtReply yet); 6 the AT command is not allowed through AtLine.

### AtLine

- The app runs the whole modem with AT lines, the same ones the terminal and the AT+MENU use: one line per AtLine (a trailing CR or LF is ignored), at most 128 bytes, through the same parser and dispatch, so it takes exactly what the AT commands take (S registers, AT+BEACON, AT+NAME, AT+WAP, AT+WSTA, AT+FWD, AT+PUB, AT+DIR, AT+SCAN, AT+FOUND?, AT+WIFI?, AT&W, ATZ, AT&V, ATI, ATH and the rest).
- The answer is AtReply frames with everything the line printed, exactly as the terminal would show it (CR LF line ends, info lines, the modem's ATV setting), ending with its result code; the last frame has flags bit 0 set. Long output (AT&V, AT+FWD?, AT+DIR?) spans several frames of up to 240 text bytes. AT+DIR? and AT+SCAN finish later: their lines follow as they come, then OK (AT+SCAN after its 5 s window).
- One AtLine at a time for the whole modem: a second one before the final AtReply, from any session, gets Error 5.
- Refused with Error 6 (nothing runs, no AtReply): AT+MODE=, AT+SIMNET=, AT+MENU, AT+VOICE, ATO, ATA, ATD, ATDT, ATDP, ATDV, and AT+FB (it dumps the screen as binary onto the host stream, which would break session 0's frames). The queries AT+MODE? and AT+SIMNET? only read and are allowed. Voice calls are placed and answered with Call and Answer.
- Passwords: AT+WAP? shows the hotspot password as `********` (the terminal still shows it, as before), AT+WSTA? always masks, the line is never echoed and is wiped after it runs. To rename the hotspot the app sends `AT+WAP=<ssid>,<password>` with a password the user types.
- An AtLine's output never reaches the terminal, and the terminal's never lands in an AtReply. If the terminal starts its own AT+DIR? or ATZ while an AtLine's listing or scan runs, the AtLine's ends with ERROR. If the AtLine's session closes, its listing or scan stops silently. An AtLine AT+DIR? is ERROR while the terminal's own listing is still printing, and AT+SCAN is ERROR while any scan runs.
- ATH and ATZ hang up a voice call (its owner then gets Ended). While a data call (radio, also dialing or ringing), a Wi-Fi call or a bridge is up they are refused with Error 6, so an app never ends the terminal's call or takes its NO CARRIER.

### Typical flows

- Start: Hello (HelloAck), Register, then Heartbeat every 2 s.
- Call out: Call; CallState dialing; then NoAnswer, Declined or Ended, or CallState training and connected. The apps run their scrambler handshake with ControlOut and ControlIn, each sends VoiceReady, CallState shows flags bit 0, then VoiceOut and VoiceIn (on push to talk tiers TalkKey down, Floor mine, talk, TalkKey up). Hangup; Ended, then CallState idle.
- Call in: Ring every 3 s; Answer (or Decline); CallState training, connected; the rest as above. RingEnded, AnsweredElsewhere or Declined when the ring stops without this app.

### Between the apps (control messages)

What the two voice apps of a call say to each other through ControlOut and ControlIn (`voice/src/control.rs`; the modem never reads it). ControlIn is a byte stream (the far modem cuts it as it likes), so each message is a 2 byte little endian length, then the message: a type byte and its body. A length of 0 or over 1024 means the stream is broken: the call stays muted. Messages are sent only when needed: once the voice slots run, control bytes move in small listener pieces.

| Type | Name | Body | Sent |
|---|---|---|---|
| 0x01 | Commit | `SHA-256("FLOWTRON COMMIT" + caller hello)` (32) | Caller, at CallState connected |
| 0x02 | Hello | answerer hello (`voice/src/scrambler.rs`) | Answerer, only after the commit was taken |
| 0x03 | Reveal | caller hello | Caller, after the answerer's hello checked |
| 0x10 to 0x13 | Link request, offer, join, sealed | `voice/src/link.rs` | Linking devices, see below |
| 0x20 | Sealed Hello | sealed `FLOWTRON HELLO v1` | Each side as soon as its handshake finished (key confirm) |
| 0x21 | Mute | sealed 1 byte (1 muted, 0 not) | On a change of our mute, or at the start when already muted |
| 0x22 | Remove device | sealed: device key (32), person key signature (64) over `LFD3K REMOVE v1` and the device key | After the trust decision, for each of our own devices published as removed |

Sealed means `Session::seal` with the call's keys (4 byte counter, ciphertext, full 16 byte tag), the same counter as the voice frames. There is no floor message: the push to talk floor and voice-ready are the modems' (TalkKey, VoiceReady).

The engine's call, in order: CallState connected; commit, hello, reveal; each side's sealed Hello. The peer is live once its sealed Hello opens; then the trust verdict for the name the user sees (the name dialed, or the caller's name on a call answered; a cert naming someone else is never Checked) and the Connected event with the plan and the two words. Audio is held both ways (nothing sent, nothing played) until the verdict is Checked or the user presses WORDS MATCH (stored) or TALK ANYWAY (this call only); a Conflict (`NOT THE <NAME> YOU CHECKED`) stays muted. Then removals, if any, and VoiceReady. Mic audio goes out as VoiceOut only while CallState flags bit 0 is set and, on a push to talk tier, while Floor says mine; VoiceIn is opened, decoded and played through a jitter buffer 2 frames deep in duplex, 1 in push to talk; a frame lost in the middle of speech is concealed by the codec. A device removal from the peer is applied only when the person key of the peer's cert signed it and the peer is checked.

Linking (spec 7.2) runs in a call between the two devices. "Link a device" shows a 6 digit code (single use, wiped once a link request uses it, or after 5 minutes). "Link to my name" takes the code (spaces around it ignored) and sends the link request once a call to the other device is live; the offer answers only a request, so a wrong code makes it send nothing after the join message, and the joiner gives up 60 s plus 30 voice frames of the tier after its request with `link failed` (the link can then be started again). After `Linked` the joining app saves its identity: it keeps its own device key and label and takes the person key and name.

App side of the protocols:
- AtLine one at a time (a queue); an AtLine refused with Error 6 or 5 ends its entry; 20 s without the final AtReply ends it too.
- The Save / Discard bar compares AT&V's settings lines (`E`, S registers, TX POWER, WIFI AP, PUB, FWD, BEACON), the AT+FWD? list and AT+WAP? (masked) with the copy taken after the last AT&W or ATZ (or at start); setting a hotspot or client password always shows it, since a masked password cannot be compared. DISCARD is refused during a call (ATZ hangs up a voice call).
- A ring switches to the CALLS screen whatever screen is open and plays a ring tone (440 plus 480 Hz, 2 s on, 4 s off) until it is answered, declined, or the ring stops (7 s after the last Ring).
- Start-up errors show in a message box and are added to `voice-pc.log` in the data folder. The window closes when the modem thread stops.
- A hotspot rename sends `AT+WAP=<name>,<password>` with a password the user types (AtLine masks the current one).
- Voice and keys: renaming signs a new cert with this device's own person key (`Identity::rename`) and starts a new voice host protocol session (Leave, then Hello and Register); the link code shows on screen while the offer lives and the app's copy is dropped when linking ends or is cancelled (`Engine::cancel_link` wipes the engine's); checked contacts come from `TrustStore::contacts`; REMOVE DEVICE on one of our own devices publishes the removal at each later call (kept in `removed.json` and given to the engine at every start), UNCHECK on a contact's device removes it locally.
- Engine helpers added for the app (no change to the call engine's behavior): `Engine::cancel_link`, `linking`, `contacts`, `peer`; `Identity::rename`; `TrustStore::contacts` and `ContactView`.
- The modem monitor (the bottom band on every screen): the modem's station and state, the newest RSSI, CONNECTION SOUNDS ON or OFF, the attribution line, and the signal scope from the modem's own Scope and AirEvent messages (`UiEvent::Scope`, `UiEvent::Air`): the last 10 s, dBm axis -130 to -30, transmit samples in the accent color, frames heard as grey spans and frames sent as accent spans, each labelled with its tier (SF5 to SF12); NO MODEM when no Scope came for 1.5 s. The built-in modem gets one sample every 50 ms from the simulated radio (the RSSI of a frame being received, else -110 dBm; 0 dBm flagged as transmit while sending). With the Save bar and a banner the screens above the band get 430 points, so every screen still fits 1280 x 720.
- Connection sounds: one chirp per AirEvent, made live (no recorded clips): up-chirps over 600 to 2400 Hz whose sweep length follows the tier's symbol time, x1.5 per SF in place of x2 (SF12 a 256 ms sweep, SF5 a 15 ms flutter), for the frame's real airtime (40 ms to 1.2 s); the preamble part plain, the rest with each sweep starting at a pseudo-random point like data symbols; frames heard with a second harmonic and a little softer. Every frame chirps only while the modem is dialing, ringing or training or the link resyncs, and for 2 s after a call or attempt ends; a Hangup or CallReject sent or heard always chirps (NO CARRIER), whatever the state says yet. While a call is connected only a retrain's own frames chirp (TierSet, TierAck, and Keepalive probes within 2 s of one), at a quarter of the level, never voice, Data, Ack or listener frames; idle is silent, so beacons and scans make no sound. Mixed into the speaker (and the `--record` WAV, which goes on 2.3 s after a call ends so its NO CARRIER chirps are in) by the modem thread at about -20 dBFS, never in the sound card's callback; a chirp is limited to the headroom left, so it never clips the call audio or the ring tone. Settings, About: CONNECTION SOUNDS ON or OFF, kept in `app-prefs.txt` in the data folder (`connection_sounds=on` or `off`; default ON). Script command `sounds on|off`.
