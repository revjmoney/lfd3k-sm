## Foreword

This specification is an AXIS / LFD3K-SM specification, published by Rev. J. Money as part of the V223.LRA protocol stack. It is not an ITU-T Recommendation.

V223.LRA.LINK describes the over the air data link that two LRA FLOWTRON DATAMASTER 3000 SERIAL MODEM (LFD3K-SM) stations use to find each other, place a call, train to the fastest workable speed, move bytes reliably in both directions, follow the radio conditions up and down, and hang up. It was written from the LFD3K-SM reference implementation, release r.420, so that anyone can build a station that interoperates with it without reading that code.

The umbrella part, V223.LRA, describes how this part fits with V223.LRA.CMPRS (compression on the air), V223.LRA.90 (voice) and V223.LRA.92 (the FLOWTRON SCRAMBLER), and defines conformance classes, capability signalling and the registration policy for every number this part uses.

Where this part and the reference implementation disagree, the reference implementation of release r.420 is authoritative for this revision and the disagreement is a defect in this document; report it to the editor.

## 1 Scope

This part specifies:

- the radio parameters of the LoRa modulation used on the calling channel (frequency, bandwidth, coding rate, sync word, preamble, header mode, CRC) and the ladder of eight speed tiers, SF12 to SF5;
- the time on air formula that every timer in this part is derived from;
- the frame format (air identifier, 5 byte header, frame types, header flags) and the exact payload of every data link frame;
- call setup, ringing, answering and training (CallReq, CallAck, CallReject, Train, TierSet, TierAck and the training probe);
- half duplex turn taking, the selective repeat ARQ (window, chunking, selective acknowledgement) and flow control;
- keepalive, automatic retrain up and down, resync after loss, and hang-up;
- discovery: Beacon, ScanReq and ScanResp, their timing and air manners, and the privacy modes ON, QUIET and HIDDEN;
- the timers and their values.

This part does not specify the host interface of a modem (the AT command set, result codes and S register numbering are implementation features of LFD3K-SM, mentioned only where they name a configuration value), the format of compressed payloads (V223.LRA.CMPRS), voice (V223.LRA.90) or the scrambler (V223.LRA.92). It does not give legal advice; see the informative regulatory notes in V223.LRA.

## 3 Terms and definitions

- **3.1 station**: one LFD3K-SM modem (or an independent implementation of this part) with one radio.
- **3.2 station name**: the name a station is called by: 1 to 16 bytes, each a printable ASCII character (0x20 to 0x7E), not containing `:` (0x3A). Station names compare without regard to ASCII letter case.
- **3.3 calling channel**: the single radio channel on which all frames of this part are sent (clause 6.1).
- **3.4 tier**: one row of the speed ladder (clause 6.3): a LoRa spreading factor at the fixed bandwidth and coding rate. Tier index 0 is SF12 (slowest), index 7 is SF5 (fastest). "Faster" and "higher" mean a larger tier index.
- **3.5 robust tier**: SF12, tier index 0. Every station listens on the robust tier whenever it is not in a connected call.
- **3.6 caller**: the station that starts a call. **answerer**: the station that accepts it.
- **3.7 call id**: an 8 bit number chosen by the caller that marks every frame of one call. The value 0 marks discovery frames.
- **3.8 frame**: one LoRa packet: the air identifier, the 4 remaining header bytes and a payload.
- **3.9 airtime(t, n)**: the time on air of a frame of n bytes on tier t, from the formula of clause 6.4, in microseconds; **air_ms(t, n)** is `floor(airtime(t, n) / 1000) + 1` milliseconds.
- **3.10 RTO(t)**: the retransmission timeout of tier t: `3 * air_ms(t, 205) + 100` ms.
- **3.11 SNR x4**: a signal to noise ratio in units of 0.25 dB, as a signed integer (13 means 3.25 dB).
- **3.12 S7, S20, S21, S22, S31**: the configuration values of a station named after the reference implementation's S registers (clause 5.6).
- **3.13 turn**: the right to transmit during a connected call in data timing (clause 9.1).
- **3.14 burst**: the frames a station sends back to back while it holds the turn. At most four, or eight when CAP_BULK is agreed and more than four chunks are outstanding at the start of the turn (clause 9.1).
- **3.15 chunk**: the unit of the ARQ: up to 200 bytes of user data with one sequence number.
- **3.16 discovery frame**: a Beacon, ScanReq or ScanResp (or a type 15 voice discovery frame, V223.LRA.90).
- **3.17 privacy mode**: one of ON, QUIET and HIDDEN (clause 11.6).
- **3.18 pinned name**: a station name the user has put in the station's directory on purpose; only pinned names may call a HIDDEN station.

## 5 Conventions

### 5.1 Requirement keywords

The key words MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, RECOMMENDED, NOT RECOMMENDED, MAY and OPTIONAL in this document are to be interpreted as described in BCP 14 [RFC2119] [RFC8174] when, and only when, they appear in all capitals, as shown here.

### 5.2 Numbers, bytes and bits

- Numbers written `0x..` are hexadecimal. Byte strings in test vectors are written as hexadecimal byte pairs separated by spaces, first byte on the air first.
- Multi-byte integers on the air are **little endian** (least significant byte first) unless a clause says otherwise. `u8`, `u16`, `u32` are unsigned; `i16` is two's complement signed.
- Bit 0 of a byte is its least significant bit; bit 7 its most significant. "Byte 1 bits 7 to 4" is the high nibble of byte 1.
- Byte offsets count from 0 at the first byte of the frame (the air identifier) unless a clause says "payload offset".

### 5.3 Strings

A **name field** is a length byte L followed by L bytes. In this part every name field holds a station name (clause 3.2), so 1 <= L <= 16, unless a clause says the field may be empty.

### 5.4 Time

All times are in milliseconds unless stated. A station keeps a monotonic millisecond clock; elapsed time is computed with wrapping 32 bit unsigned subtraction. Timers are evaluated at least every 10 ms (Annex E.1).

### 5.5 Pseudo-random numbers

Where this part says "a uniform random number in 0..=N", any source is acceptable whose values are spread roughly evenly and differ between stations; it need not be cryptographic. The reference implementation's generator is described in Annex E.4 for information.

### 5.6 Configuration values

| S20 | Training margin, SNR x4 added to a tier's floor before the tier is used | 20 (5 dB) | 0 to 200 |
| S21 | Tier cap: the highest tier index this station will use | 7 (SF5) | 0 to 7 |

A station MAY offer other means to set these values; only their effect on the air is specified here.

## 6 Physical layer

### 6.1 Calling channel

All frames of this part SHALL be sent and received on one channel with centre frequency **918 500 000 Hz** (918.5 MHz).

NOTE: On an SX126x radio with a 32 MHz reference, the RF frequency word is `918500000 * 2^25 / 32000000 = 0x3968_0000`.

### 6.2 Modulation and packet parameters

Every frame SHALL be sent, and every station SHALL listen, with the parameters of Table 1, on the tier (spreading factor) a clause of this part names.

**Table 1: LoRa parameters common to every tier**

| Parameter | Value |
|---|---|
| Modulation | LoRa chirp spread spectrum [SX126X] |
| Bandwidth | 500 kHz |
| Coding rate | 4/5 |
| Low data rate optimization | Off on every tier |
| Header | Explicit (variable length) |
| Payload CRC | On |
| IQ | Standard (not inverted) |
| Sync word | 0x1424 (SX126x registers 0x0740 = 0x14, 0x0741 = 0x24) |
| Preamble | 8 symbols on SF7 to SF12; 12 symbols on SF5 and SF6 (as programmed, see Table 2) |
| Payload length | 5 to 255 bytes |

NOTE 1: The sync word 0x1424 is the SX126x form of the LoRa "private network" sync word (0x12 in the one byte form used by SX127x radios). It keeps LFD3K-SM frames apart from LoRaWAN public networks, which use 0x3444 (0x34).

NOTE 2: At 500 kHz the longest symbol (SF12) is 8.192 ms, below the 16 ms where the datasheet recommends LDRO; LDRO is therefore off everywhere. A receiver programmed with LDRO on would not decode these frames.

A receiver SHALL accept a frame only if the radio reports a valid explicit header and a correct payload CRC. Transmit power is not specified by this part; it is set by the station's configuration and the law where it operates (V223.LRA, informative regulatory notes).

### 6.3 The tier ladder

**Table 2: Tiers**

| Index | Tier | Name shown | Air rate (bit/s) | SNR floor (dB) | SNR floor (x4) | Preamble (symbols) | Tsym (us) |
|---|---|---|---|---|---|---|---|
| 0 | SF12 | LORA SF12 BW500 | 1172 | -20.0 | -80 | 8 | 8192 |
| 1 | SF11 | LORA SF11 BW500 | 2148 | -17.5 | -70 | 8 | 4096 |
| 2 | SF10 | LORA SF10 BW500 | 3906 | -15.0 | -60 | 8 | 2048 |
| 3 | SF9 | LORA SF9 BW500 | 7031 | -12.5 | -50 | 8 | 1024 |
| 4 | SF8 | LORA SF8 BW500 | 12500 | -10.0 | -40 | 8 | 512 |
| 5 | SF7 | LORA SF7 BW500 | 21875 | -7.5 | -30 | 8 | 256 |
| 6 | SF6 | LORA SF6 BW500 | 37500 | -5.0 | -20 | 12 | 128 |
| 7 | SF5 | LORA SF5 BW500 | 62500 | -2.5 | -10 | 12 | 64 |

The air rate is the nominal LoRa bit rate `SF * (BW / 2^SF) * 4/5`, rounded to the nearest integer; it is a label, not a timing value. The symbol time is `Tsym = 2^SF / 500 kHz = 2^SF * 2 us`.

The **SNR floor** is the lowest SNR at which a tier is considered usable. The tier chosen for an SNR `s` (x4) with a margin `m` (x4) is

`best_tier(s, m)` = the highest tier t (largest index) with `floor_x4(t) + m <= s`, or SF12 if there is none.

A station SHALL compute `best_tier` exactly as above wherever this part uses it.

NOTE: At a fixed bandwidth the measured SNR does not depend on SF, so one SNR measurement taken on SF12 predicts every tier.

### 6.4 Time on air

All timers of this part are derived from the following integer formula, which is the [SX126X] LoRa time on air for BW 500 kHz, CR 4/5, explicit header, CRC on and LDRO off. For a payload of `n` bytes (the whole frame, air identifier included) on spreading factor `SF`:

- `Tsym_us = 2^SF * 2`
- for SF >= 7: preamble = (8 + 4.25) symbols; `k = 28`
- for SF <= 6: preamble = (12 + 6.25) symbols; `k = 20`
- `num = 8*n - 4*SF + k + 16`; `blocks = ceil(num / (4*SF))` if `num > 0`, else 0
- payload symbols = `8 + 5 * blocks`
- `airtime_us = Tsym_us * preamble_quarters / 4 + payload_symbols * Tsym_us`, where `preamble_quarters` is 49 for SF >= 7 and 73 for SF <= 6.

`air_ms(t, n) = floor(airtime_us / 1000) + 1`.

A station SHALL use this formula (not a measured duration) for every timer this part derives from airtime, so that both ends of a call compute the same values. Annex A.2 tabulates the results.

### 6.5 Signal quality measurements

For each received frame the radio reports:

- **SNR x4**: the packet SNR in units of 0.25 dB as a signed value. On SX126x this is the signed byte SnrPkt of GetPacketStatus, used unchanged.
- **RSSI**: the packet RSSI in dBm (SX126x: `-RssiPkt / 2`).

Where this part sends an SNR in a frame it is the SNR x4 of the most recently received frame of the relevant kind, as an `i16`.

### 6.6 Listening

A station listens on exactly one tier at a time. A station SHALL listen on SF12 whenever it is idle, ringing, dialing or in any training state except the probe (clause 8), and in resync (clause 10.5). During the probe and while connected it listens on the call's tier. After every transmission a station SHALL return to receive on the tier it is listening on. A frame sent on a tier the receiver is not listening on is not heard.

## 7 Frame format

### 7.1 Header

Every frame is a header of 5 bytes followed by a payload of 0 to 250 bytes; the whole frame is at most 255 bytes.

**Table 3: Frame header**

| Offset | Field | Content |
|---|---|---|
| 0 | Air identifier | 0xD1. Bits 7 to 4 (0xD) identify the LFD3K-SM family; bits 3 to 0 (1) are the air protocol version |
| 1 | Type and flags | Bits 7 to 4: frame type (Table 4). Bits 3 to 0: flags (Table 5) |
| 2 | Call id | The call this frame belongs to; 0 for discovery frames |
| 3 | Seq | Data: the ARQ sequence number (clause 9.3). Type 15 slot frames: the slot number (V223.LRA.90). Otherwise 0 |
| 4 | Ack | Ack: the cumulative acknowledgement (clause 9.3). Type 15 slot frames: the same. Otherwise 0 |

A sender SHALL set Seq and Ack to 0 in frames for which Table 3 gives them no meaning, and a receiver SHALL ignore them there.

### 7.2 Frame types

**Table 4: Frame types**

| Type | Name | Tier sent on | Call id | Payload (clause) |
|---|---|---|---|---|
| 0 | (invalid) | | | Never sent; a receiver drops it |
| 1 | CallReq | SF12 | call | 7.4.1 |
| 2 | CallAck | SF12 | call | 7.4.2 |
| 3 | CallReject | SF12 | the rejected call's | empty |
| 4 | Train | SF12 | call | 7.4.3 |
| 5 | TrainAck | (not sent) | | 7.4.4 |
| 6 | Data | call tier | call | 7.4.5 |
| 7 | Ack | call tier | call | 7.4.6 |
| 8 | TierSet | SF12 in training; call tier in a call | call | 7.4.7 |
| 9 | TierAck | the tier its TierSet was heard on | call | 7.4.7 |
| 10 | Hangup | the sender's listening tier | call | empty |
| 11 | Keepalive | call tier (SF12 in resync) | call | 7.4.8 |
| 12 | Beacon | SF12 | 0 | 11.2 |
| 13 | ScanReq | SF12 | 0 | 11.4 |
| 14 | ScanResp | SF12 | 0 | 11.5 |
| 15 | Voice | see V223.LRA.90 | 0 or call | First payload byte is a sub-type (V223.LRA.90) |

All 15 type values are allocated. New functions are added as type 15 sub-types or under a new air protocol version (V223.LRA, registration policy).

### 7.3 Header flags

**Table 5: Header flags (byte 1 bits 3 to 0)**

| Bit | Mask | Name | Defined on | Meaning |
|---|---|---|---|---|
| 0 | 0x1 | MORE | any frame sent in a connected call in data timing | Another frame of the same burst follows at once (clause 9.1) |
| 1 | 0x2 | PING | Keepalive | Please reply (clause 10.1) |
| 2 | 0x4 | LZ | Data | The payload is compressed per V223.LRA.CMPRS |
| 1 | 0x2 | FEC | Data | This chunk is in a parity group (clause 9.5). On a Keepalive the same bit is PING |
| 3 | 0x8 | PARITY | Data | The payload is parity for the group, not a chunk (clause 9.5). On a ScanReq the same bit is VOICE |
| 3 | 0x8 | VOICE | ScanReq | Stations with voice names answer with a voice scan answer (V223.LRA.90) |

A flag has a meaning only on the frame types listed. A sender SHALL clear every flag bit not defined for the frame type it sends; a receiver SHALL ignore such bits.

### 7.4 Payloads of call frames

#### 7.4.1 CallReq (type 1)

| Payload offset | Field | Content |
|---|---|---|
| 0 | caller | name field: the caller's station name |
| 1 + L1 | callee | name field: the station name dialed |
| 2 + L1 + L2 | caps | OPTIONAL capability byte (Table 6) |

**Table 6: Capability byte**

| Bit | Name | Meaning |
|---|---|---|
| 0 | CAP_LZ | The sender takes Data frames compressed per V223.LRA.CMPRS |
| 1 | CAP_BULK | Bulk ARQ (clause 9): window 16, burst of 8 while more than 4 chunks are outstanding, 16 bit SACK |
| 2 | CAP_LZ_STREAM | Stream compression above ARQ (V223.LRA.CMPRS clause 14). When agreed it replaces per frame compression |
| 3 | CAP_FEC | The sender can apply burst parity (clause 9.5). The parity covers the bytes stored in ARQ, which are the compressed stream when CAP_LZ_STREAM is agreed |
| 4 to 7 | (must be 0) | A CallReq or Train whose capability byte has any of these bits set is malformed and SHALL be dropped |

A caller SHALL include the capability byte only when it sets at least one capability (with r.420: only when S31 = 1). An absent byte means no capabilities.

NOTE: Builds older than r.420 reject a CallReq that carries the byte. A station that must call such a build sends no capability byte.

#### 7.4.2 CallAck (type 2)

Empty, or one capability byte holding the **agreed** capabilities (those both ends offered). A receiver SHALL treat anything other than exactly one byte with bits 4 to 7 clear as "no capabilities". The answerer SHALL send the byte only when it is non-zero, so a caller that offered nothing receives the empty form.

#### 7.4.3 Train (type 4)

| Payload offset | Field | Content |
|---|---|---|
| 0 | cap | u8 tier index: the highest tier the answerer allows (its S21) |
| 1 | snr | i16: the SNR x4 at which the answerer heard the caller's CallReq |
| 3 | caps | OPTIONAL capability byte: the agreed capabilities |

The answerer SHALL send the 4 byte form only when the agreed capabilities are non-zero (which implies the caller offered and is a new build); otherwise it SHALL send the 3 byte form. In a voice call a 4 byte answer token follows (7 or 8 bytes in all, V223.LRA.90). A receiver SHALL drop a Train whose length is not 3, 4, 7 or 8, whose first byte is not a tier index 0 to 7, or whose capability byte (4 and 8 byte forms) has bits 4 to 7 set.

#### 7.4.4 TrainAck (type 5)

Reserved. A conforming station SHALL NOT send it. A receiver accepts as well formed exactly 3 bytes whose first byte is a tier index, and SHALL otherwise ignore it.

#### 7.4.5 Data (type 6)

The header Seq field carries the ARQ sequence number. The payload is one chunk of 1 to 200 bytes of user data, or, with flag LZ, its compressed form per V223.LRA.CMPRS (which SHALL decompress to at most 200 bytes).

#### 7.4.6 Ack (type 7)

The header Ack field carries the next sequence number the receiver expects. The payload is the SACK bitmap (clause 9.3.3): exactly one byte when CAP_BULK is not agreed, or exactly two bytes (little endian) when it is agreed. A receiver SHALL drop an Ack of any other length.

#### 7.4.7 TierSet (type 8) and TierAck (type 9)

TierSet: one byte, the tier index asked for (0 to 7). In the training of a voice call a 4 byte answer token follows (5 bytes, V223.LRA.90). TierAck: exactly one byte, the tier index granted. A receiver SHALL drop either frame if the tier index is not 0 to 7 or the length is not as stated.

#### 7.4.8 Keepalive (type 11)

Two bytes: the sender's SNR x4 (i16) of the last frame it heard of this call (0 if none yet). With flag PING it asks the peer to reply; without PING it is a reply or a training probe answer.

#### 7.4.9 CallReject (type 3) and Hangup (type 10)

Empty payloads. A sender SHALL send them empty; a receiver SHALL ignore any payload bytes on them. A Keepalive whose payload is not exactly 2 bytes is still a Keepalive but carries no SNR.

### 7.5 Receiving frames

A station SHALL process a received LoRa packet as follows, in order:

1. If it is empty, or its first byte is not 0xD1, it is foreign traffic: ignore it silently. A station SHALL NOT answer or log foreign traffic as an error.
2. If it is shorter than 5 bytes or longer than 255 bytes, drop it.
3. If the type is 0, drop it. If the type is 15 and the payload is empty or its first byte is a sub-type the station does not implement (V223.LRA.90), drop it.
4. If the payload does not have the exact shape this part gives for its type (clauses 7.4 and 11), drop it.
5. A CallReq is handled by clause 8.3 whatever the station's state. Discovery frames are handled by clause 11. Type 15 frames are handled by V223.LRA.90.
6. Any other frame is ignored unless the station has a call (or call attempt) whose call id equals the frame's call id.

## 8 Call setup and training

Annex B gives the state machines as tables; this clause states the rules.

### 8.1 Dialing

To call station name N, an idle caller SHALL:

1. choose a call id. It SHALL NOT be 0. The reference implementation uses the low 8 bits of its millisecond clock with bit 0 set (an odd number); an implementation SHOULD choose call ids so that two callers in range are unlikely to use the same one;
2. build a CallReq (clause 7.4.1) with its own station name, N, and its capability byte if it offers any capability;
3. send it on SF12, and again every **3000 ms** (PERIOD) until a CallAck or Train of this call arrives, the attempt is cancelled, or **S7** seconds have passed since the dial;
4. listen on SF12 between sends.

If S7 runs out while dialing, the caller SHALL send one Hangup (on SF12) and report NO ANSWER. A CallReject of this call ends the attempt as BUSY (nothing further is sent). A CallAck moves the caller to *await train* (it keeps waiting for the Train; it does not send further CallReqs). A Train is handled by clause 8.5 in either state.

### 8.2 Answering and ringing

A station SHALL treat a CallReq as addressed to it when the callee name equals its station name (ignoring ASCII case) and the call id is not 0. A CallReq not addressed to it is ignored. A station in HIDDEN mode first applies clause 11.6.

On a CallReq addressed to it:

- **Idle and free**: the station enters *ringing* for that call id, records the SNR x4 the CallReq was heard at and whether its capability byte had CAP_LZ, and alerts its user (RING) at once and every 3000 ms while it rings. Ringing sends nothing on the air.
- **Same call id as its current call or attempt**: it is a repeat. The station refreshes its ringing (or, if it answered and has not yet received a TierSet, sends its CallAck and Train again at once). It updates the recorded SNR and, while not connected, the caller's capabilities.
- **Busy** (any other call or call attempt, or engaged in a non radio call of its own): the station SHALL send a CallReject carrying the CallReq's call id on SF12, and SHALL NOT disturb its own call.

Ringing ends without an answer when no repeat of the CallReq has been heard for **7000 ms** (`2 * PERIOD + 1000`) or S7 seconds have passed since the ring began. A ringing station that declines the call (the user hangs up while ringing) SHALL send one CallReject.

A station MAY answer automatically after a configured number of rings (LFD3K-SM: S0).

### 8.3 Answering: CallAck and Train

To answer a ringing call the answerer SHALL:

1. fix its own cap tier from S21 and decide whether it offers compression (S31);
2. queue a CallAck (with the agreed capability byte, clause 7.4.2) and a Train (clause 7.4.3) on SF12, in that order;
3. enter *await TierSet*, listening on SF12;
4. repeat the CallAck and Train every **3000 ms** while no TierSet has arrived, and at once on each repeat of the CallReq;
5. give up after S7 seconds in this state by sending a Hangup on SF12.

The SNR in the Train is the SNR x4 at which the answerer heard the most recent CallReq of this call.

### 8.4 Capability agreement

The agreed capabilities are those set both in the caller's CallReq capability byte and in the answerer's own offer. Each bit is agreed on its own. The answerer sends the agreed bits in the CallAck and as the 4th byte of the Train. The caller SHALL take the agreed capabilities from the Train (the frame it cannot connect without), so both ends always agree. A capability is in force for the whole call when it is agreed; offers are read when the call starts.

CAP_BULK (bit 1) is a data call capability. The reference offers it whenever it sends the capability byte, which is when S31 is 1, and then also sets CAP_LZ, CAP_LZ_STREAM, and CAP_FEC. A voice call SHALL NOT offer CAP_BULK: voice slot frames carry an 8 bit SACK (V223.LRA.90). An older peer that does not implement bit 1 ignores it and does not echo it, so the call stays on the classic window and the one byte Ack.

### 8.5 Tier choice (caller)

On the first Train of its call, the caller SHALL:

1. compute `snr = min(SNR x4 at which it heard the Train, snr field of the Train)` (the worse of the two directions);
2. compute `cap = min(own S21 tier, cap field of the Train)`;
3. pick `t = min(best_tier(snr, S20), cap)`;
4. send a TierSet carrying t on **SF12** and enter *await TierAck*, listening on SF12;
5. repeat that TierSet every `3 * air_ms(SF12, 6) + 200` ms (**821 ms**) until a TierAck arrives, or give up after S7 seconds in this state with a Hangup on SF12.

The caller reports TRAINING with the SNR of step 1 (informative).

### 8.6 Granting a tier (answerer)

On a TierSet of its call while in *await TierSet* or *probe*, the answerer SHALL:

1. grant `g = min(asked tier, own S21 tier)`;
2. send a TierAck carrying g on the tier the TierSet was heard on (SF12 during training);
3. switch to listening on tier g and enter *probe* with the window
   `W = air_ms(SF12, 6) + (3 * air_ms(g, 7) + 200) + 50 + air_ms(g, 7) + 120` ms (Annex A.3).

If W passes without a PING, the answerer SHALL return to *await TierSet* on SF12 (the caller's next TierSet will name a slower tier). A second TierSet while in probe is handled the same way (a new grant).

### 8.7 Probe (caller)

On a TierAck with tier a not above the tier it asked for, the caller SHALL:

1. lower its cap to `min(cap, a)` (a lower grant is the answerer's cap) and switch to tier a;
2. send a Keepalive with PING on tier a (the training probe) and wait `P(a) = 3 * air_ms(a, 7) + 200` ms;
3. if nothing arrives, send one more probe on the same tier and wait `P(a)` plus a random 0 to 50 ms;
4. if nothing arrives again, step one tier slower: send a TierSet for the next slower tier on SF12 (clause 8.5 step 4) and continue there; if tier a is already SF12, send a Hangup and report NO CARRIER.

A TierAck naming a tier above the one asked for SHALL be ignored.

### 8.8 Connecting

- The answerer, in *probe*, on a Keepalive with PING on its tier, SHALL reply with a Keepalive (no PING) on that tier carrying the SNR x4 of the probe, and becomes **connected**.
- The caller, in *probe*, on any Keepalive, Data or Ack of its call on the probe tier, becomes **connected** and processes that frame as a connected frame.

On connecting a station resets its SNR average to the SNR of the connecting frame (clause 10.2), takes the turn (clause 9.1) and starts the call's timers. A station reports CONNECT with the tier (informative).

### 8.9 Ending setup

During any setup state a station that receives a Hangup of its call SHALL end the attempt (a ringing station ends silently; others report NO CARRIER). A station whose user hangs up during setup sends the Hangup pair of clause 10.6, except a ringing station, which sends one CallReject. A station that gives up because S7 ran out sends a single Hangup on its listening tier.

## 9 Data transfer

This clause applies to a connected call in **data timing**, which is every data call and a voice call until its voice slots start (V223.LRA.90 replaces clauses 9.1 and 9.2 while the slots run).

### 9.1 Turn taking

The radio is half duplex and the two stations share one channel, so they take turns.

1. On connecting, each station holds the turn.
2. A station SHALL transmit a frame of the call only while it holds the turn, except a Hangup or CallReject, which may be sent at any time.
3. While holding the turn a station sends a **burst** of at most BURST frames back to back. BURST is **4**. When CAP_BULK is agreed and more than 4 chunks are outstanding in the send window at the start of the turn, BURST is **8**. It SHALL set MORE on a frame when another frame of the burst follows at once, which is when the frame is not turn ending, fewer than BURST minus 1 frames of the burst have been sent before it, and the station has another frame ready. Turn ending frames (Keepalive with or without PING, and TierSet and TierAck sent in a call) SHALL NOT carry MORE. A turn with nothing else ready ends after the one frame that was ready, so a single chunk (a typed line) does not grow into a long burst.
4. After sending a frame without MORE the station hands the turn to its peer. It takes the turn back by itself if it hears nothing of the call for `air_ms(t, n) + G(t)` ms after that frame, where n is that frame's length, t the call tier, and `G(t)` the turn gap below; the **answerer adds 100 ms** to this wait, so that two silent stations do not restart in step.
5. On hearing a frame of the call with MORE set, a station SHALL NOT transmit; it takes the turn back if no further frame of the call starts within `air_ms(t, 205) + G(t)` ms of that frame. On hearing a frame of the call without MORE, it holds the turn and starts a new burst.

The **turn gap** is `G(t) = max(40, floor(2 * Tpre_us(t) / 1000) + 20)` ms, where `Tpre_us(t)` is the preamble time `12.25 * Tsym` on SF7 to SF12 and `18.25 * Tsym` on SF5 and SF6 (Annex A.2).

NOTE: A radio reports a channel busy only once it has detected the peer's preamble, so the gap covers two preambles.

### 9.2 What a station sends in its turn

When it holds the turn a station SHALL choose its next frame in this order:

1. queued control frames (TierSet, TierAck, a Keepalive reply owed from the probe), oldest first;
2. an **Ack**, if at least one Data frame has been received since its last Ack;
3. a **Keepalive with PING**, if one is due (clause 10.1);
4. a **Data** frame (clause 9.3.1), if one is due;
5. a **Keepalive reply** (no PING), if a PING was received and not yet answered. An Ack or Data frame sent after the PING counts as the answer.

If nothing is due the station sends nothing and keeps listening.

### 9.3 Selective repeat ARQ

#### 9.3.1 Sender

- User bytes are cut into chunks of at most **200** bytes (CHUNK). Bytes MAY be added to the newest chunk until it is first sent; a sent chunk never changes.
- At most **W** chunks (WINDOW) are outstanding: queued or sent and not yet released by a cumulative acknowledgement. Further user bytes wait until a chunk is released. **W is 8.** When CAP_BULK is agreed, **W is 16** for the whole call. Storage for 16 chunks MAY be reserved even when the call uses 8.
- Each chunk has a sequence number: the oldest outstanding chunk has the sender's base number; the next ones follow, counting modulo 256.
- The chunk to send next SHALL be the oldest chunk never sent; if every outstanding chunk has been sent, the oldest chunk that is not individually acknowledged and was last sent at least `RTO(t)` ms ago (t is the current call tier). A resent chunk SHALL carry the same sequence number and the same user bytes.
- Each chunk goes out in one Data frame (clause 7.4.5), compressed or not per clause 9.4.

#### 9.3.2 Receiver

The receiver keeps a **receive base**: the sequence number of the oldest chunk not yet delivered to its user. On a Data frame of its call with sequence number s:

1. let `off = (s - receive base) mod 256`. If `off >= W` (clause 9.3.1) or the user data is longer than 200 bytes, the chunk is discarded;
2. else, if a chunk is already held at that offset, the frame is a duplicate and is ignored;
3. else the chunk is stored.

In every case (stored, duplicate or discarded) the receiver owes an Ack (clause 9.2). Held chunks are delivered to the user strictly in sequence order with no gaps; the receive base advances by one for each chunk the user has wholly taken.

NOTE: Flow control is implicit: a receiver whose user does not read keeps its receive base, so a sender that runs ahead has its frames discarded and resends them after RTO.

#### 9.3.3 Acknowledgement

An Ack frame carries:

- in the header Ack field, `a = receive base + c` (mod 256), where c is the number of consecutive chunks held starting at the receive base;
- in its payload, the SACK bitmap. When CAP_BULK is not agreed the payload is one byte: bit i (i = 0 to 6) is 1 when the chunk with sequence number `a + 1 + i` is held and lies within the receive window (offset below 8). Bit 7 is 0. When CAP_BULK is agreed the payload is two bytes, little endian, forming a 16 bit word: bit i (i = 0 to 14) is 1 when the chunk `a + 1 + i` is held and lies within the receive window (offset below 16). Bit 15 is 0. A station SHALL NOT send the two byte form unless CAP_BULK was agreed. A station that did not agree SHALL ignore an Ack that is not exactly one byte. A station that agreed SHALL take a one byte Ack as that byte with the high byte clear, and a two byte Ack as the 16 bit word.

On an Ack of its call the sender SHALL:

1. compute `adv = (a - base) mod 256`. If adv exceeds the number of outstanding chunks, or any of the first adv outstanding chunks has never been sent, ignore the Ack;
2. release the first adv chunks and set base to a;
3. for each SACK bit i that is 1, mark the chunk at offset `1 + i` from the new base as individually acknowledged, if it exists, has been sent, and lies within W. Individually acknowledged chunks are not resent.

### 9.4 Compression on the air

When the CAP_LZ capability is agreed and CAP_LZ_STREAM is not (clause 8.4), the sender SHALL compress each Data frame's chunk on its own as V223.LRA.CMPRS specifies and send the compressed form, with flag LZ, only when V223.LRA.CMPRS says it saves enough; otherwise it sends the chunk plain. A receiver SHALL decompress every Data frame that carries flag LZ (whether or not it agreed); a frame that fails to decompress, or decompresses to more than 200 bytes, SHALL be treated as not received (no Ack is owed for it). When CAP_LZ_STREAM is agreed, V223.LRA.CMPRS clause 14 applies instead.

### 9.5 Burst parity

When CAP_FEC is agreed, a station MAY protect a group of 1 to 7 plain chunks with one parity frame. The code is a shortened systematic Reed-Solomon code over GF(256) with one parity symbol per byte column. In characteristic 2 that symbol is the XOR of the column. One missing chunk is rebuilt from the parity and the chunks that arrived. Two missing chunks are not rebuilt; ARQ resends them (clause 9.3). The receiver reads the siblings from its window, which is 8 or 16 (CAP_BULK).

The parity frame is a Data frame with flag PARITY and header sequence 0. It is not an ARQ chunk: it consumes no window slot and it is not acknowledged on its own. Its payload is `n` (1 byte, 1 to 7), then `n` sequence numbers in group order, then the XOR of the chunk lengths (1 byte), then the XOR of the chunk bytes. A shorter chunk is treated as zero past its own length, and the byte XOR is as long as the longest chunk. A receiver that did not agree CAP_FEC SHALL ignore a PARITY frame. A malformed payload is ignored.

Each plain chunk that is in the group is sent with flag FEC. The receiver SHALL NOT deliver those chunks to its user until the parity frame is applied or `4 * RTO(t)` ms have passed since the newest such chunk, so the chunks are still held for the rebuild. Delivery then follows clause 9.3.2. Acks are not delayed: `have` is updated when the chunk arrives, and an Ack is still owed.

A station SHALL send parity only after it has seen a hole (a SACK bit set, or a resend while the SNR average is under the step down line). After 16 new chunks with no new hole, and while the SNR average is not under that line, it SHALL stop. On a classic burst a group of four chunks is closed at once and the parity frame may use one slot past the four frame burst. On a bulk burst of eight the group is seven chunks and the parity frame is the eighth, so the turn does not grow a ninth frame. A shorter group is closed after one airtime of a full chunk with nothing left unsent, so a short tail is still covered. While parity is on, the sender's resend timeout is `RTO(t)` plus one chunk airtime, so a fifth classic frame is not mistaken for a loss.

Voice calls do not offer CAP_FEC. Their capability byte stays CAP_LZ only, and voice slots do not send parity frames.

While CAP_FEC is agreed and parity is still covering the loss (fewer than eight chunks have been sent a third time since the tier last changed), a station SHALL NOT take the SNR step down of clause 10.3. The silence step down (clause 10.4) is unchanged. SF5 to SF6 drops the air rate from 62500 to 37500 bps, about 40 percent; one parity frame on four data frames is 25 percent more airtime than the data alone, and only while the hole persists.

## 10 Link maintenance: keepalive, retrain, resync, hang-up

In this clause t is the current call tier, and `off` is 0 for the caller and `floor(RTO(t) / 2)` for the answerer. "Heard" means any frame of the call was received. Clauses 10.1, 10.3 and 10.4 apply in data timing; V223.LRA.90 gives the changes while voice slots run.

### 10.1 Keepalive

- A connected station that has heard nothing for `2 * RTO(t) + off` ms SHALL send a Keepalive with PING carrying its SNR x4 (clause 7.4.8).
- While unanswered it SHALL send another PING each time `RTO(t) + r` ms have passed since the last, r a uniform random number in `0..=floor(RTO(t) / 4)` drawn for each PING.
- Anything heard ends the count of unanswered PINGs.
- A station that receives a PING SHALL answer it per clause 9.2 item 5.

### 10.2 SNR average

Each connected station keeps an SNR average A in SNR x4 units with eight times the resolution, `A8`. On connecting (and on leaving resync) `A8 = 8 * s` for the SNR x4 s of the frame just heard. For every later frame of the call heard with SNR x4 s:

`A8 = A8 + s - trunc(A8 / 8)`, and the average is `A = trunc(A8 / 8)`,

where trunc divides toward zero (32 bit signed arithmetic). This is an exponentially weighted average with weight 1/8.

### 10.3 Retrain

A station SHALL evaluate the following every tick while connected, it has no retrain request pending, and at least `2 * RTO(t)` ms have passed since the last tier change:

- **Step down**: if a slower tier exists and `A < floor_x4(t) + S20 - 8`, and this has held for at least `off` ms, request the next slower tier. If CAP_FEC is agreed and parity is still covering the loss (clause 9.5), the station SHALL NOT take this step. The silence step down (clause 10.4) is not waived.
- **Step up**: if a faster tier f exists with f not above the call's cap, and `A > floor_x4(f) + S20 + 12` has held continuously for at least `10000 + off` ms, request f.

The call's cap is the lower of the two S21 caps as learned in training, lowered further by any TierAck that grants less than asked.

To **request** tier r a station SHALL send a TierSet carrying r on the current tier (a turn ending frame) and mark r pending. If no TierAck comes within `RTO(t) + q` ms, q a uniform random number in `0..=floor(RTO(t) / 2)`, it sends the TierSet again, at most 3 sends in all; after the third wait it drops the request (clause 10.5 recovers if the peer moved).

On a **TierSet** of its call while connected:

- the caller, if it has a request of its own pending, SHALL ignore it (the caller's request wins a collision);
- otherwise the station drops any pending request of its own, grants `g = min(asked, own S21 tier)`, sends a TierAck carrying g on the tier the TierSet was heard on, and switches to g.

On a **TierAck** carrying a while a request for p is pending: if `a <= p` the station drops the request, lowers the call's cap to a if `a < p`, and switches to a; otherwise it ignores the TierAck.

**Switching** to a tier sets the time of the last tier change, moves listening and sending to that tier, and restarts the step up and step down hold times. A station reports RETRAIN with the new tier (informative).

### 10.4 Step down on silence

If a station has heard nothing for at least `4 * RTO(t) + off` ms and at least 2 PINGs are unanswered, and it has no retrain request pending, it SHALL request the next slower tier (if any), once per period of silence.

### 10.5 Resync

If a station has heard nothing for at least `8 * RTO(t)` ms it SHALL enter **resync**:

1. drop any pending request, set the call tier to SF12 and listen on SF12, and hold the turn;
2. start the resync clock now, or, if the call was already on SF12, at the time the last frame was heard;
3. the **caller** sends a Keepalive with PING on SF12 at once and then every `3 * air_ms(SF12, 7) + 200` ms (**944 ms**); the answerer only listens and answers PINGs;
4. if S22 seconds pass on the resync clock, the station ends the call (NO CARRIER) without sending anything.

When a station in resync hears any frame of its call it SHALL return to connected on SF12, reset its SNR average (clause 10.2), and, if the call was on another tier before, report RETRAIN SF12. The **caller** then picks `r = min(best_tier(min(s, p), S20), cap, the tier one below the tier the call was on when resync began)`, where s is the SNR x4 of the frame heard and p is the SNR the frame carries (a Keepalive's payload) or s if it carries none, and requests r (clause 10.3) if r is above SF12.

### 10.6 Hang-up

A station that hangs up a call in any state after answering or dialing (training, probe, connected, resync) SHALL drop every queued frame, send **two** Hangup frames on its listening tier without waiting for the turn, and become idle. A station that receives a Hangup of its call SHALL end the call and report NO CARRIER (a ringing station ends the ring silently).

## 11 Discovery and privacy

### 11.1 Air manners

All discovery frames (Beacon, ScanReq, ScanResp, and the type 15 voice discovery frames of V223.LRA.90):

- SHALL be sent on SF12 with call id 0, Seq 0 and Ack 0;
- SHALL be sent only while the station has no call or call attempt of any kind (radio or otherwise), including dialing and ringing;
- SHALL NOT be sent while the radio is receiving a frame or transmitting (listen before talk);
- SHALL be spaced at least **10000 ms** apart (DISC_GAP): a station sends at most one discovery frame of any kind in any 10 s.

A station SHALL ignore any discovery frame that carries its own station name.

### 11.2 Beacon (type 12)

| Payload offset | Field | Content |
|---|---|---|
| 0 | name | name field: the sender's station name |
| 1 + L | services | u8, Table 7 |
| 2 + L | heard | u8: how many other stations the sender has heard in the last 900 s, at most 255 |
| 3 + L | time quality | u8: 0 in this revision; receivers SHALL ignore it |

**Table 7: Services byte**

| Bit | Name | Meaning |
|---|---|---|
| 0 | ACCEPTS | The station answers calls by itself (auto answer is on) |
| 1 | FORWARD | The station bridges answered calls to a published service |
| 2 | HOTSPOT | The station's Wi-Fi hotspot is on |
| 3 | VOICE | Voice names are registered at this station (a hint; V223.LRA.90) |
| 4 to 7 | (reserved) | Sent as 0, ignored on receipt |

The payload length SHALL be exactly `4 + L`; a Beacon of any other length is malformed.

### 11.3 Beacon schedule

In privacy mode ON a station SHALL send a Beacon `300000 + j` ms after it starts, where j is a uniform random number in `0..=60000` drawn for each wait, and again `300000 + j` ms after each Beacon it sent. A call (any state) suspends the schedule; when the call ends the wait starts again from a fresh `300000 + j`. A Beacon that falls due while the station's own scan collects answers, inside the 10 s spacing, or while the channel is busy, waits until it may go. In QUIET and HIDDEN no Beacon is sent.

### 11.4 Scanning: ScanReq (type 13)

| Payload offset | Field | Content |
|---|---|---|
| 0 | name | name field: the scanning station's name |
| 1 + L | scan id | u8: a uniform random number 0 to 255 drawn for each scan |

The payload length SHALL be exactly `2 + L`. A station that scans SHALL send one ScanReq (when clause 11.1 allows; a scan whose ScanReq cannot go out within 14000 ms of the request fails), then collect for **5000 ms** from the moment its ScanReq went out every ScanResp (and voice scan answer, V223.LRA.90) whose scan id matches. A station in HIDDEN SHALL NOT scan. A station implementing V223.LRA.90 sets flag VOICE on its ScanReq; others SHOULD send it clear.

### 11.5 Answering scans: ScanResp (type 14)

| Payload offset | Field | Content |
|---|---|---|
| 0 | name | name field: the answering station's name |
| 1 + L | services | u8, Table 7 |
| 2 + L | snr | i16: the SNR x4 at which the ScanReq was heard |
| 4 + L | scan id | u8: copied from the ScanReq |

The payload length SHALL be exactly `5 + L`.

A station in mode ON or QUIET that hears a ScanReq (not carrying its own name) while it has no call and no answer already waiting SHALL answer it once:

1. pick a slot k, a uniform random number in `0..=10` (11 slots of **250 ms**);
2. at `250 * k` ms after the ScanReq was heard: if sending now would break the 10 s spacing, drop the answer; if the channel is busy, move to slot `k + 1` (if k was 10, drop the answer); otherwise send the ScanResp (or, for a ScanReq with flag VOICE at a station with voice names, the voice scan answer of V223.LRA.90 in its place).

A station in HIDDEN SHALL NOT answer scans.

### 11.6 Privacy modes

**Table 8: Privacy modes**

| Mode | Beacons | Answers scans | May scan | Who may call it |
|---|---|---|---|---|
| ON | yes | yes | yes | anyone |
| QUIET | no | yes | yes | anyone |
| HIDDEN | no | no | no | only pinned names |

In HIDDEN a station SHALL drop a CallReq whose caller name is not a pinned name before clause 8.2 sees it: it sends nothing at all (no CallReject) and does not ring, so the caller sees NO ANSWER. A HIDDEN station MAY dial out; its CallReq carries its name by necessity. A station SHOULD let the user choose the mode; ON is the default.

### 11.7 What a station learns (informative)

A station typically keeps a directory of stations heard: from Beacons, ScanReqs, ScanResps, a CallReq addressed to it, and the CallAck or Train of a station it dialed. For a ScanResp the useful SNR is the worse of the two directions (`min(SNR heard, snr field)`), and the best tier is `best_tier(SNR, S20)`. In HIDDEN mode the reference implementation lets a ScanReq or an overheard ScanResp only refresh a name it already knows, while Beacons still add new names (which give no right to call it).

## 12 Relation to the other parts

- Compression: V223.LRA.CMPRS defines the payload of a Data frame with flag LZ and the gain rule.
- Voice: V223.LRA.90 defines frame type 15 and its sub-types, the voice forms of Train (with a 4 byte answer token) and of the training TierSet (5 bytes), voice discovery, and the slot timing that replaces clauses 9.1, 9.2, 10.1, 10.3 and 10.4 while voice slots run. Voice call setup reuses clauses 8.5 to 8.8 and clause 10 unchanged except where V223.LRA.90 says.
- Scrambler: V223.LRA.92 runs entirely between the two voice applications; this part never sees keys or plaintext.
- Capabilities and versions: V223.LRA defines how the air identifier, the capability byte and type 15 sub-types evolve.

## 13 Conformance

A station conforms to V223.LRA.LINK when it meets every MUST and SHALL of clauses 6 to 11 that applies to the functions it implements, with these minimums:

- it implements clauses 6, 7, 8, 9, 10 and 11.1 completely, for both the caller and the answerer role;
- it answers scans (clause 11.5) and honours the privacy modes it offers; it implements at least mode ON; QUIET and HIDDEN are RECOMMENDED;
- Beacons (clause 11.3) and scanning (clause 11.4) are RECOMMENDED; a station that sends either SHALL follow those clauses;
- compression is OPTIONAL as an offer, but every station SHALL decompress Data frames with flag LZ (clause 9.4) when it ever offers CAP_LZ; a station that never offers CAP_LZ never receives one from a conforming peer.

A conformance claim SHALL state the revision of this part, the privacy modes implemented, and whether compression is offered. V223.LRA defines the conformance classes that combine this part with the others.

## Annex D (informative): Rationale

- **One wide channel, many speeds.** All tiers use 500 kHz so that every tier meets the 500 kHz minimum 6 dB bandwidth of US 47 CFR 15.247 digital modulation without hopping. Speed comes from the spreading factor alone, and one SNR measured on SF12 predicts all tiers.
- **Train on SF12, then probe.** The robust tier reaches both ends whenever any tier would. The probe on the chosen tier proves it works both ways before CONNECT; one retry per tier keeps a single lost probe from costing a tier.
- **The worse direction decides.** The caller uses the lower of the SNR it heard and the SNR the answerer reports, so neither direction is pushed past its floor.
- **The answerer waits longer.** Half an RTO more before it pings, steps or retrains, and 100 ms more before it takes a silent turn back, so the two ends never act in lock step and collide again.
- **Selective repeat with a small window.** Eight 200 byte chunks fill a burst pair at SF5 and keep memory small on a microcontroller; the SACK byte saves resending what arrived. CAP_BULK raises that to sixteen chunks and a burst of eight, and only while more than four chunks are already outstanding, so a typed line still yields the turn after one frame. The extra storage is eight chunks in each direction (3200 bytes of payload) plus a few dozen bytes of slot metadata. The reference keeps the slots statically, so a classic call simply does not use the upper eight.
- **The turn gap was not shortened for the longer burst.** `G(t)` and the answerer's extra 100 ms are the silence timeout a station uses when it hears nothing. A station that hears the peer takes the turn at once, so those waits are not added to a transfer whose frames arrive. They cover a 10 ms poll plus a radio that reports the channel busy only after a preamble. Shortening them was not measured on hardware, and the simulated gain from doing so would be zero on a clean transfer. A simulated SF5 transfer of 4096 incompressible bytes, with the SNR loss draw skipped, moves from 53.6 kbps to 54.4 kbps one way, and from 26.5 kbps to 26.9 kbps in each direction when both sides send. A 16 byte turn takes 5 ms either way. These figures are simulated, not measured on the air.
- **Resync is a soft landing.** Instead of dropping the call on a deep fade, both ends fall to SF12 and the caller keeps asking for S22 seconds, then climbs back, never straight to the tier that just failed.

## Annex E (informative): Implementation notes

- **E.1 Tick.** The reference implementation runs its timers every 10 ms and also right after each transmission ends (from the radio's TX done interrupt). A station that only polls every 10 ms can miss an immediate reply.
- **E.2 Radio contract.** "Busy" should be true from the moment a preamble is detected and during transmission. Guard against a false preamble that never becomes a frame: the reference driver re-arms receive after `preamble + 16` symbols without a valid header, and after `airtime(t, 255) + 2 ms` at most.
- **E.3 Call id.** Only 8 bits, chosen per call, mark a call. Two calls in range that happen to share an id can cross talk; a future revision may add addressing.
- **E.4 Random numbers.** The reference implementation uses xorshift32 (shifts 13, 17, 5). Retry jitter is seeded per call from `call_id * 0x01010101 XOR m`, with m = 0x9E3779B9 for the caller and 0x5BD1E995 for the answerer, bit 0 forced to 1. Discovery numbers are seeded from the FNV-1a hash of the station name XOR the start time rotated left by 16, bit 0 forced to 1. A value in `0..=N` is `x mod (N + 1)`.
- **E.5 Receive gain.** The reference SX1262 driver selects the boosted receive gain (register 0x08AC = 0x96).
- **E.6 SNR saturation.** The SX126x SnrPkt saturates on strong signals; the margin S20 absorbs the error at the top of the ladder.
