Result codes: OK 0, CONNECT 1, RING 2, NO CARRIER 3, ERROR 4, BUSY 7, NO ANSWER 8.
Verbose CONNECT reads CONNECT <tier name> <air bps>/ARQ on radio (CONNECT <tier name> <air bps>/ARQ/LZ when the call compresses) and CONNECT WIFI TCP on a Wi-Fi call. RETRAIN lines are verbose only.

Notes:
- ATD strips one leading T or P, as Hayes does. To dial a name that starts with T or P, use the full prefix: ATDT TOM or ATDP PAT (ATDTOM would dial OM).
- Names compare case-insensitively.
- Escape: no data for S12 (1/50 s), then three S2 characters each less than S12 apart, then nothing for S12. Anything else is data. S12=0 turns the escape off.
- Data mode is 8-bit clean: a RETRAIN during data mode is held and printed after the OK of the escape (verbose mode). AT&V shows the current tier and the last 4 retrains. ATO prints CONNECT with the current tier. NO CARRIER prints right after the received data that fits in the host buffer, never later.
- A tier above a modem's S21 cap is never used: asked for one, the modem acks its cap instead, and the asker stops asking above it.
- ATH during a call prints NO CARRIER; with no call it prints OK. ATZ restores the saved settings (S registers, echo, verbose, hotspot, client network, forwards, publish; power-on defaults when nothing was loaded or saved) and hangs up silently.
- ATA with nothing ringing prints NO CARRIER; ATA in online command mode (a call is up) prints ERROR and the call stays up.
- A partial command line typed before a call connects (during RING or while dialing) is dropped at CONNECT.
- The station name is 1 to 16 printable ASCII characters without `:` (Config::new refuses anything else), so a dial like `BBS:1` is always host:port, never a radio name. Radio dial names containing `:` print ERROR.
- ATI prints three lines: LORA FLOWTRON DATAMASTER 3000 SERIAL MODEM - LFD3K-SM, then v0.1.0 r.420 BL4Z3B4ND ULTR4M0D3M, then S0N1C B00M R4D10 PR0 MAX.
- ATI gets a fourth line `LAST CRASH: <note>` only when the previous boot ended in a panic (the note is `file:line`, up to 64 printable characters). With no crash it prints three lines, as before.
- AT&V prints `RADIO OK` or `RADIO FAIL <code> ERR 0x<4 hex>` after the TX POWER line, once the firmware has brought the radio up. Code -1 is a BUSY timeout, -2 no chip, -3 bad config; the hex word is the chip's device errors.
- S30 is the only signed register: ATS30=-9 is accepted (a leading minus works for S30 only), ATS30? prints the signed value, anything outside -9 to 22 prints ERROR. AT&V shows `TX POWER S30=<n> dBm chip, about <n+12> dBm out`.
- Command lines are up to 128 bytes. `+` command arguments split on commas: an SSID, forward name or password may not contain a comma. SSID and password are taken as typed; the fields of AT+FWD are trimmed, so `AT+FWD=bbs, bbs.example.com, 23` works.
- ATDT order: a forward name (any case) first, then `host:port`, else a radio dial. Use `ATDT`, not bare `ATD`, for host names that start with T or P.
- Wi-Fi dial (forward or host:port): `DIALING <target>` (verbose), then `CONNECT WIFI TCP` (numeric 1) when the platform's TCP connect succeeds, and data mode. No fake speed in the connect string. A refused or failed connect prints NO CARRIER; no connect within S7 seconds prints NO CARRIER and closes the attempt. When the far end closes, everything it sent is shown first (data mode), then NO CARRIER. The escape, ATO (prints CONNECT WIFI TCP again) and ATH (NO CARRIER, also while dialing) work as on a radio call; ATZ hangs up silently. ATDT or ATA while any call is up prints ERROR. A Wi-Fi dial also prints ERROR while the previous connection's close is still pending (the platform has not released that socket yet); try again a moment later.
- Wire mode: telnet (T) or raw (R), from the forward, or for host:port T on port 23 and R otherwise. In T mode the modem is a telnet client: it answers WILL ECHO, WILL SGA and WILL BINARY with DO, DO SGA and DO BINARY with WILL, DO NAWS with WILL NAWS plus an 80 x 25 window size, refuses everything else (DONT, WONT), never sends anything first, strips all commands and subnegotiations from what it receives (a subnegotiation is dropped whole up to IAC SE, however long; IAC IAC becomes one 0xFF; while the server does not send BINARY, CR NUL becomes CR), and sends 0xFF as IAC IAC. While our sending direction is not BINARY (the server has not said DO BINARY), CR LF goes out as CR LF and any other CR as CR NUL (RFC 854); a CR that ends the data so far is held until the next byte or 50 ms, then sent as CR NUL. Raw mode passes bytes untouched.
- Bridge (AT+PUB set): a radio call this modem answers is connected to the published forward only, never to any other host. The radio caller sees its normal CONNECT; what it sends before the wire is up is buffered (up to 2 KB, then the radio window holds it). The local host stays in command mode and sees `BRIDGE <name>` (verbose) once the wire connects, and NO CARRIER when the bridge ends. If the wire fails, does not connect within S7 seconds, or closes (after what it sent has reached the caller, at most S7 seconds), the radio call is hung up and the caller sees NO CARRIER. If the radio call drops, or the host types ATH or ATZ, the wire is closed. ATO during a bridge prints ERROR.
- One call at a time: a radio caller during a Wi-Fi call gets BUSY.
- `Modem::wire_state()`: 0 none, 1 dialing, 2 online, 3 bridging. `call_state()` shows a Wi-Fi call as dialing (1) or online (4, or 5 in online command mode). Lights during a Wi-Fi call: OH on from the dial, CD on once connected (and until NO CARRIER), SD and RD lit for 100 ms after wire traffic once connected, HS and EC off, no tier.
- AT&V adds `WIFI AP <ON|OFF> <ssid>  STA <ssid|OFF>`, `PWSHOW <0|1>` (1 while the generated hotspot password may be shown on the OLED), `PUB <name|NONE>` and `FWD <count>` after the RADIO line. When the firmware has reported the modem task's stack high-water mark (`lfd3k_set_stack_free`), AT&V ends that group with `STACK FREE <bytes>` (omitted until reported).
- AT&W sets a save-wanted flag the platform takes (`Modem::take_save_request`) and reads with `Modem::settings()`. `Modem::load_settings` applies a loaded copy at boot, including S0 auto-answer and S30. ATZ restores that copy.
- SimNet (AT+SIMNET): while it is on, AT&V prints `RADIO SIMNET <ip>` in place of the RADIO OK line (`RADIO SIMNET <ip> NET FAIL` when the firmware could not open the UDP socket; the modem stays on SimNet, `AT+SIMNET=<ip>` again retries and `AT+SIMNET=0` goes back to the SX1262), nothing is sent on RF (the SX1262 is in standby), `lfd3k_status_t.simnet` is 1 and the OLED labels the HS light `SI`. Datagrams go to `<ip>:4210` and only datagrams from `<ip>` are taken. A frame on a tier the modem is not listening on is not heard, as on the air. The idle scope shows the simulated channel (the RSSI the peer reports while a frame is received, else -110 dBm). The V4 tells the peer it hears it at +8 dB, -70 dBm. Steps for Rev: docs/simnet.md.
- `Modem::take_wifi_changed()` is true once after AT+WAP (any form that took effect), AT+WSTA (any form that took effect), ATZ or a settings load; the platform then re-reads `Modem::settings()` (a reference) and re-applies Wi-Fi. `note_ap_client_joined` asks for a save only when the saved copy still had the password shown, and the platform writes `Modem::saved_settings()` (never the live copy), so a join persists only that flag and other unsaved settings stay unsaved. The platform holds a Wi-Fi apply while any call is up (any wire state or radio call) and runs it after the call ends, and skips one that equals the config already applied (it keeps a hash, not the passwords).
- The hotspot password may be shown on the OLED (`Modem::show_ap_pass`) until a device joins (`note_ap_client_joined`), AT&W saved with a client network set, or the user sets a hotspot password of their own with `AT+WAP=<ssid>,<pass>` (only the generated first-boot password is shown); the flag is part of the saved blob.
- Secrets at rest: both the hotspot and the client password are stored unencrypted in the V4's flash (NVS and flash encryption are off). `AT+WSTA=0` then `AT&W` removes the client one from the saved settings, but NVS may keep the old bytes in flash until that page is reused.
- AT&V adds `HEAP MIN <bytes>` (the lowest free heap since boot, `lfd3k_set_heap_min`, reported once a second like STACK FREE, omitted until reported), right after STACK FREE.
- The wire socket has TCP keepalive (idle 30 s, interval 5 s, 4 probes), so a host that vanished ends the call with NO CARRIER.
- Discovery air manners: beacons, scans and scan answers go out only while no call exists (radio or Wi-Fi, including dialing and ringing) and never more than once per 10 s per modem. A beacon is due 300 s plus a random 0 to 60 s after start, after the last beacon, or after the last call ended; it waits while a scan collects answers or the channel is busy. A modem answers a ScanReq once, in a random slot of 0 to 10 times 250 ms; if the channel is busy at its slot it tries the next slot, and gives up after slot 10 or when it sent any discovery frame in the last 10 s. Random numbers come from an xorshift seeded with the station name and the start time.
- AT+SCAN waits for the 10 s spacing before sending (so a second scan right after the first starts up to 10 s later) and gives ERROR if its ScanReq cannot go out within 14 s. A call starting while a scan runs (ATDT, or a caller ringing) ends it with ERROR. Switching to HIDDEN before the ScanReq went out also ends it with ERROR (nothing is sent). ATZ ends it silently. Commands typed during the 4 s window run as usual.
- An AT+DIR? listing that is still printing ends silently when data mode starts (ATO or a CONNECT), so the data stream stays 8-bit clean.
- The SNR in a SCAN line is the worse of the two directions (how we heard the answer and how the other modem heard our ScanReq); the tier is the fastest one that SNR allows with the S20 margin.
- Directory: up to 32 entries, names compare case-insensitively, our own name is never added (also when two modems share a name or our own frames come back). Filled from beacons, scan answers, ScanReqs (in HIDDEN mode a ScanReq or an overheard scan answer only refreshes a name already known; beacons still add new names, which gives them no right to call a HIDDEN modem), a caller's CallReq to us (call id not 0), and the CallAck or Train of the station we dialed. When full, the least recently heard unpinned entry is replaced; pinned entries never are. The blob (for the platform's NVS) keeps every pinned entry and the 8 most recently heard others, with name, services and best tier; SNR and age start fresh after a boot (age shows `-` until heard again).
- `Modem::take_dir_save()` is true once after AT&W, or after a directory change once 60 s have passed since the last save (an entry added, replaced or removed, a pin, or new services or best tier; a beacon that only refreshes SNR asks for nothing). The firmware writes `Modem::directory().to_blob()` (through `lfd3k_take_dir_save`) to NVS key `dir` in the lfd3k namespace, held until no call is up like the settings, and at boot, after the settings (so an AT+NAME name is in force), hands the blob to `lfd3k_load_directory`, which parses it straight into the live directory (`Modem::load_directory_blob`, no second copy on the modem task stack). A missing or refused blob leaves the directory empty.
- HIDDEN mode: a CallReq to us from a name that is not pinned in the directory (heard entries do not count) is dropped before the call logic sees it, so nothing at all is sent (no RING on our side, no CallReject; the caller sees NO ANSWER). Pinned callers (AT+DIR=+NAME) ring and connect as usual. No beacons, no scan answers, and AT+SCAN is ERROR (a ScanReq carries our name). Dialing out (ATD or the menu) is allowed in HIDDEN: the owner chose to transmit, and the CallReq carries our name. Only AT+SCAN is refused.
- Beacon services byte: bit 0 auto-answer on (S0 above 0), bit 1 a forward is published, bit 2 the hotspot is on. A beacon also carries how many stations this modem heard in the last 15 minutes.
- AT&V adds `BEACON <mode>` and `DIR <entries>` after the FWD line. `MODE LFD3K-SM` (the running firmware mode) follows the DIR line.
- Settings blob v2 is 900 bytes (the beacon mode byte at 897, CRC at 898). A v1 blob (899 bytes) from phase 3 still loads, with the mode ON, and the next save writes v2.
- Settings blob v3 is 917 bytes: the station name (length byte, 16 bytes) follows the beacon byte at 898, CRC at 915. Length 0 means the firmware's name. v2 (900 bytes) and v1 (899) blobs still load with no stored name, and the next save writes v3. Renaming drops our new name from the directory (never our own name).
- Compression (S31): the caller adds one capability byte to its CallReq when its S31 is 1 (no byte means no compression, the form older builds send; an older build cannot take a CallReq that has the byte, so set S31=0 to call one). The answerer agrees when its own S31 is 1 too and says so with the same byte on its CallAck and as a 4th byte of its Train (sent only to a caller that offered). The caller takes the answer from the Train, which it cannot connect without, so both ends always agree. The call compresses when both offered; CONNECT then ends in `/ARQ/LZ` (also on ATO). S31 is read when the call starts; changing it during a call takes effect on the next call. Each 200 byte ARQ chunk is compressed on its own when its Data frame is built (a resend compresses the same chunk to the same bytes) and goes out compressed only when that saves at least 8 bytes. A received compressed frame that does not decode is dropped without an ack, so it is sent again. Wi-Fi calls are not compressed.
- AT&V ends with `LZ ON|OFF RATIO <n.n>` for the current or last radio call: Data payload bytes before compression over Data payload bytes on the air, both directions and resends included, one decimal, `1.0` when nothing was sent. The S register line now ends with `S31=<n>`.
- S31 is stored in the settings blob as flags bit 4, inverted (set means S31 = 0), so the blob stays v2 at 900 bytes and every saved v2 blob loads with compression on.
- Setup menu (AT+MENU, core/src/menu): an 80x24 screen for a CP437 terminal (SyncTERM). Keys: arrows (`ESC [ A..D` or `ESC O A..D`), Enter (CR, LF or CR LF), Esc (an ESC with nothing after it for 150 ms), Backspace (BS or DEL), Tab (next row), and the first letter of an item (jumps to it, and on the main menu opens it when no other item starts with that letter). Other escape sequences are swallowed whole. While the menu is open every host byte is a menu key: the AT parser and the `+++` escape see nothing.
- Menu screens: Directory and Scan (name, best tier, age, SNR, RSSI, pin, offers; Enter leaves the menu and dials the entry exactly like `ATDT <name>`, S scans like AT+SCAN with the answers landing in the list, P pins, A adds a name and pins it, D deletes after a Y or N); Link Status (call state, tier and ladder, last SNR, RSSI and frame tier, retrains, throughput in call data bytes per second both ways (bytes the host or a bridge moved in or out of the call, so 0 while the menu holds a plain call), compression and its ratio, the Wi-Fi line; updated once a second); Settings (station name, edited in a text box that runs AT+NAME, empty for the firmware's name; privacy mode; S30; S21; S0; S31; S32); Forwards (8 slots; A adds, Enter or E edits host, port and mode, D deletes after a Y or N, P publishes or unpublishes); Wi-Fi (hotspot on or off, name, password; client network and password, forget; the live status line); About (banner, version, release name, tagline, radio status, stack and heap, last crash, directory count, privacy mode); Save settings (AT&W); Exit menu.
- Menu edits compose the AT line the user would type (for example `ATS30=7`, `AT+BEACON=QUIET`, `AT+WSTA=<name>,<password>`, `AT+FWD=<name>,<host>,<port>,<T|R>`, `AT+DIR=+<name>`) and run it through the AT parser and dispatch, so they take exactly what the AT commands take; fields are also checked as they are typed in with the same rules. A changed value is live at once (like the AT command) and stays after a reboot only after Save settings. Directory pins and deletes are immediate, like AT+DIR. Passwords show as `********` always, typing one shows one `*` per character, and the typed text and the composed line are wiped after use.
- Leaving the menu: Esc on the main menu, or Exit menu. With unsaved changes (the live settings differ from the saved profile; the status line shows UNSAVED) it asks: Y or Esc discards (back to the saved profile, like ATZ but without hanging up, so it also drops AT changes made before the menu that were never saved), S saves and leaves, N stays. So Esc always gets out: Esc closes a text box, Esc goes back to the main menu, Esc leaves, Esc discards. Leaving clears the screen (colors reset, cursor shown) and prints OK; a NO CARRIER that came while the menu was open is printed first, and RING after OK when a caller still rings (ATA then answers). A scan still running ends silently.
- While the menu is open nothing else reaches the terminal: result codes and info lines are held back, RING shows in the status line, and call data stays in the call (the window then holds the far end, as in online command mode). Mid-call (`+++` then AT+MENU), leaving returns to online command mode and ATO goes back to the call. A call that connects while the menu is open (auto-answer with S0) closes the menu first, then CONNECT prints as usual.
- Menu drawing: rows are composed from the live state, hashed, and only rows whose hash changed are sent (after a key, an event, or once a second). A row goes into the host output whole, and only while 96 bytes stay free behind it; otherwise it waits for the next tick or for the host to read, so a slow terminal only slows the redraw and the host output ring stays 1 KB. The bottom right cell is never written (the status line ends with an erase to end of line), so no terminal scrolls.
- Boot to menu (S32 = 1, saved by AT&W): the first host bytes after boot open the menu and are dropped. ATZ does not open it. S32 is stored in the settings blob as flags bit 5 (set means 1), so every older blob loads with S32 = 0. AT&V's S register line now ends with `S32=<n>`.
- Menu preview: `cargo run -p lfd3k-sim --example menu_preview -- <dir>` writes the sessions as `.ans` files, and `py -3.14 tools/menu_preview.py <dir>` replays them on a strict 80x24 terminal, checks that a normal session, one drained 7 bytes per millisecond and a fresh full paint end on the same screen, and draws the PNGs in docs/phase4-bench/menu.

## Front panel (OLED)

- 0.96 inch SSD1306 (128x64) front panel drawn by the panel task (core 0, priority 2, 20 fps cap). The modem task publishes a status copy each loop; the panel never calls the core.
- Top row: eight blinky lights OH CD SD RD HS EC DC AA, boxed and filled when lit. SD and RD are held lit 80 ms so short bursts stay visible. DC is lit while a radio call compresses (`/ARQ/LZ`, status bit 6). The board LED (GPIO35) follows SD or RD.
- Middle: the state word (IDLE, DIALING, RING, TRAINING, ONLINE, CMD) or, in a call, the tier (`SF7 BW500`) with `ONLINE 21875 BPS` (or `CMD ...` in online command mode) and an eight cell tier ladder. `RADIO FAIL` replaces it when the radio is not usable.
- Bottom: the station name (the live one: AT+NAME changes it within a second; `LFD3K-SM` when none), the last heard RSSI (dBm) and SNR (dB), and an RSSI bar (-130 to -30 dBm) and SNR bar (-20 to +10 dB).
- Scan radar: while an AT+SCAN (or the menu's scan) runs, the idle middle band (y 12..37) shows `SCAN` at 2x on the left, a round scope in the middle (radius 11, a dotted inner ring) with a sweep line that goes round every 1.6 s with a thinning tail, one blip per answer so far (each at a fixed place picked from its number, the newest blinking, the 12 newest drawn), and on the right the answer count at 2x with `FOUND` under it. It replaces the idle show and the scope until the scan ends. Pure function of the time and the status fields `scanning` and `scan_hits`. Mockup docs/phase2-bench/mockups/scan.png.
- Animations: OH blinks while dialing (2.5 Hz), a sweep runs across the eight tiers while training and the chosen tier flashes when training ends, idle shows a breathing carrier bar (2 s), RING flashes inverted.
- Idle animations: the idle text show (below); a breathing scope draws the live radio channel (one RSSI sample every 50 ms from the SX1262, 64 samples, transmit samples marked); the idle meters are live; the lights shuffle on an 8 s loop, with the home order restored on every fourth loop (they hold still while the scroller runs).
- Idle text show (firmware/src/idle_show.c, pure C like the renderer, every frame a pure function of the time and the facts): each 8 s loop shows one item in the band y 12..29. Items and weights: English `IDLE` 3; each of 16 more languages 1 (Russian ПРОСТОЙ, Spanish INACTIVO, German LEERLAUF, Mandarin 空闲, Japanese 待機, Hindi निष्क्रिय, Bengali নিষ্ক্রিয়, Arabic خامل, Urdu بیکار, Turkish BOŞTA, Swedish VÄNTAR, Polish JAŁOWY, Greek ΑΔΡΑΝΗΣ, Korean 대기, Hebrew סרק, Thai ว่าง; Rev's set of 2026-11-10); facts 1 each, only while known: clock `HH:MM` (24 h, only once SNTP has synced), uptime (`UP 3D 4H`, `UP 5H 12M`, `UP 12M`), chip temperature (`38C`), `HEARD <n>` (directory entries heard in the last 15 minutes, the count a beacon carries; shown while above 0), the last caller's name (the station that last called us over the radio since boot), and GPS coordinates (a hook the firmware leaves empty for now). GPS text is dropped unless `hide_location` is 0 (default 1), so screenshots never show the position. The item is picked by a hash of the loop number; an item never shows twice in a row. Latin, Cyrillic, Greek, Turkish, Swedish and Polish words and the facts use our own 5x7 font at 2x (1x when wider than 124 px; new hand-drawn glyphs П Р О С Т Й Ş Ä Ł Δ Σ, with Α Ρ Ν Η sharing the Latin shapes). Mandarin, Japanese, Korean, Hindi, Bengali, Arabic, Urdu, Hebrew and Thai are 1-bit bitmaps (16 to 18 px tall, bold; Thai gets the full 18 rows so its tone mark stays clear) rendered on the PC from the Noto fonts with real shaping (Pillow with libraqm: Devanagari and Bengali conjuncts, Arabic, Urdu and Hebrew right to left, Thai stacked marks) by tools/gen_idle_words.py into firmware/src/idle_words.h.
- Transitions, 4000 to 7000 ms into the loop (never over the lights shuffle at 1000 to 2200 ms), one of twelve by hash, equal weights: EXPLODE (2x2 cells break into flying dots and 0/1 bits that home onto the next item's pixels), BLOCKS (4x4 blocks flash inverted and go dark in random order, then the new ones flash on), SINE SCROLL (old out left, new in from the right, every column on a moving sine, 32 px wavelength, flattening as it settles), SPLIT FLAP (12 px cells flip top half then bottom half through random letters, like an airport board), TYPEWRITER (a block cursor erases the old item, types the new one a letter at a time, right to left for Arabic, Urdu and Hebrew, and blinks), DRIP MELT (columns of the old item fall out of the band at random speeds, revealing the new one from the top), GLITCH (sliced rows from both items shifted sideways, some inverted, then a snap), MATRIX RAIN (streams of tiny 0/1 bits fall down 4 px lanes and leave the new item lit), STARFIELD WARP (stars stream out of the centre, the old item shrinks away and the new one grows out), CRT POWER (squash to a line, shrink to a lingering dot, then back out into the new item), VENETIAN BLINDS (2 px slats close top to bottom and open on the new item), PIXELATE (2x2, 4x4, 8x8 block averages, swap, sharpen back).
- Scroller message: about one loop in 12 (one per group of 14 loops, never twice in a row) the text `BUILT BY: REV J. MONEY, AUTHOR OF ROTATOCAM!   OPEN SOURCE DATA MODEM RADIO TOY!` (the SCROLL_TEXT constant in idle_show.c) scrolls right to left across the panel at 2x on a moving sine wave (about 55 px/s, 20 s; the loop count follows the text length), pushing the previous item off; the loop before it skips its transition, and the next item comes in with a normal transition over the empty band.
- Facts feed: the modem task fills `panel_info_t` once a second (`panel_publish_info`, same spinlock as the status copy; the panel task hands it to `panel_render_set_info`): uptime from esp_timer, chip temperature from the ESP-IDF temperature sensor driver (range -10 to 80 C), local time once SNTP (pool.ntp.org, started once the client side has an address) has synced; the time zone is `EST5EDT,M3.2.0,M11.1.0` (Rev in South Carolina, the LOCAL_TZ constant in main.c). The SNTP callback only sets a flag under the panel lock; nothing but the modem task calls the core.
- PC check and preview: tools/panel_check renders every item into every item with every transition at 75 time steps and the scroller from every item, inside the guards and inside the band (explode dots y 12..44, sine waves y 12..31), each transition ending exactly on the new item, and the schedule over 200,000 loops (no repeats, no GPS while hidden, every item and transition used). panel_check.ps1 also writes docs/phase2-bench/mockups/idle-show.gif (every transition with its name under the panel, preview only, and the scroller) and idle-items.png (every item).
- Live channel trace: `lfd3k_poll` samples GetRssiInst (one 3 byte SPI transaction) every 50 ms while listening and marks samples taken during a transmit; the modem task hands the 64 sample ring to the panel with each status copy.
- Wi-Fi rows (idle only): the name row (y 46..52) rotates every 3 s through the board name, `AP <ssid>` (when the hotspot is on), `PW <pass>` (only while the core says `PWSHOW 1`: until a device joins the hotspot or `AT&W` saved with a client network set) and `IP <a.b.c.d>` (when the client side has an address). Each row is cut to 21 characters. The password is never drawn when `PWSHOW` is 0 and is not even handed to the renderer then. The modem task fills `panel_net_t` once a second (`panel_render_set_net`, same pattern as the trace) and wipes its copies. The idle animations and live meters are untouched.
- Wire call screens: dialing shows `DIALING` with the dots; a Wi-Fi TCP call online shows big `WIFI TCP` with `ONLINE` (or `CMD` in online command state) and no tier ladder; a radio call bridged to a forward shows big `BRIDGE` with the radio tier line (`SF7 BW500 21875 BPS`) and the ladder. A pure Wi-Fi call does not show `RADIO FAIL`.
- Bench terminal secrets (tools/lfd3k_term.py): output and logs show `********` for the rest of a `WAP ` line after ON or OFF, after `PW ` on any line, and after the comma of an echoed `AT+WAP=` or `AT+WSTA=` (also with spaces around `+` or `=`, in any case); an AT+FB dump is never written to the log, even with `--allow-secret`; `--allow-secret` lifts it on the screen only (logs are always redacted). `--shot` needs `--shot-safe` (reads AT&V, sends AT+FB only after `PWSHOW 0`) or `--allow-secret`. A `--shot` or `--log` path inside the repo docs folder is refused unless AT&V says `PWSHOW 0`.
- Boot splash for 1 s: `LFD3K-SM`, `r.420`, `BL4Z3B4ND`.
- `panel_snapshot` returns the last drawn frame (1024 bytes, SSD1306 page order, bit 0 = top row) for AT+FB. The drawing code is the pure function `panel_render` (no ESP-IDF calls) so the PC tool can render the same screens.
