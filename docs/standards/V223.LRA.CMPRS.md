## Foreword

This specification is an AXIS / LFD3K-SM specification, published by Rev. J. Money as part of the V223.LRA protocol stack. It is not an ITU-T Recommendation.

Bulletin board screens are full of repeated ANSI escape sequences, CP437 box drawing lines and runs of spaces. V223.LRA.CMPRS lets two stations that both agree compress each Data frame of a data call on its own, against a fixed dictionary of exactly that material, so that more of a screen fits each LoRa frame. It was written from the LFD3K-SM reference implementation, release r.420.

## 1 Scope

This part specifies the negotiation of compression between two stations, the compressed payload format of a Data frame, the decoding procedure and its error cases, the fixed preset dictionary, and the rule that decides whether a frame goes out compressed. It gives an encoder for information only: any encoder whose output follows clauses 8 and 10 interoperates.

## 3 Terms and definitions

- **3.1 chunk**: the user bytes of one ARQ chunk, 1 to 200 bytes (V223.LRA.LINK clause 9.3).
- **3.2 preset (P)**: the fixed 567 byte dictionary of Annex A.
- **3.3 virtual buffer**: the bytes of P followed by the bytes produced so far for the current frame.
- **3.4 token**: one literal run or one match in a compressed payload.
- **3.5 compressed payload**: the payload of a Data frame that carries flag LZ.

## 5 Conventions

The key words MUST, SHALL, SHOULD, MAY and their negatives are to be interpreted as described in BCP 14 [RFC2119] [RFC8174] when, and only when, they appear in all capitals. Bit 7 is the most significant bit of a byte. Hexadecimal is written `0x..` or as space separated byte pairs.

## 6 Negotiation

1. A caller that offers compression sets bit 0 (CAP_LZ) of the capability byte at the end of its CallReq [V223.LRA.LINK clause 7.4.1]. A caller that also offers stream compression (clause 14) sets bit 3 (CAP_LZ_STREAM) in that same byte. Bits 1 and 2 are reserved and SHALL be ignored by an implementation that does not define them.
2. The answerer agrees to each bit it also offers. It then sends those bits in its CallAck and as the 4th byte of its Train [V223.LRA.LINK clauses 7.4.2, 7.4.3, 8.4]. An answerer that does not implement clause 14 ignores bit 3 and answers with CAP_LZ alone.
3. The caller reads the agreement from the Train. Per frame compression (clauses 7 to 13) is **in force** when CAP_LZ was agreed and CAP_LZ_STREAM was not. Stream compression (clause 14) is **in force** when CAP_LZ_STREAM was agreed.
4. Offers are fixed when the call starts. A change of the local setting during a call takes effect on the next call.

While per frame compression is in force, a sender SHALL apply clause 10 to every Data frame it builds. A receiver SHALL decode every Data frame that carries flag LZ, whether or not it agreed (a conforming peer only sends one after an agreement). While stream compression is in force, clause 14 applies instead and flag LZ is not used.

## 7 Where compression applies

Compression applies only to the payload of Data frames (type 6) of a call on the air. It does not apply to any other frame type, to voice (V223.LRA.90), or to connections that do not use the air (such as a TCP call of the reference implementation). Each Data frame is compressed **on its own**: no state is carried from one frame to the next, so the ARQ may resend, reorder or lose any frame without the two ends disagreeing about the dictionary.

## 8 Bitstream format

A compressed payload is a sequence of tokens that ends where the payload ends. The first byte of each token gives its kind:

**Table 1: Tokens**

| First byte | Following bytes | Token | Meaning |
|---|---|---|---|
| `0LLLLLLL` (0x00 to 0x7F) | L + 1 bytes | literal run | Copy the next `L + 1` bytes (1 to 128) of the payload to the output as they are |
| `1MMMMMDD` (0x80 to 0xFF) | one byte `dddddddd` | match | Length `M + 3` (3 to 34); distance `((DD << 8) OR dddddddd) + 1` (1 to 1024). Copy `length` bytes from `distance` bytes back from the end of the virtual buffer |

A match copies byte by byte, in order, so its source may lie in P, in the output produced so far, or run from P into the output, and it may overlap the bytes it is writing (a distance of 1 repeats the last byte `length` times).

## 9 Decoding

A receiver SHALL decode a compressed payload `in` into an output `out` of capacity 200 bytes as follows, with `|P| = 567`:

```
ip = 0; op = 0
while ip < len(in):
    h = in[ip]; ip = ip + 1
    if h < 0x80:                       # literal run
        k = h + 1
        if ip + k > len(in):  fail Truncated
        if op + k > 200:      fail Overflow
        out[op .. op+k] = in[ip .. ip+k]; ip = ip + k; op = op + k
    else:                              # match
        if ip >= len(in):     fail Truncated
        lo = in[ip]; ip = ip + 1
        length   = ((h >> 2) AND 0x1F) + 3
        distance = (((h AND 0x03) << 8) OR lo) + 1
        v = |P| + op                   # end of the virtual buffer
        if distance > v:      fail BadDistance
        if op + length > 200: fail Overflow
        for s from v - distance, length times:
            b = P[s] if s < |P| else out[s - |P|]
            out[op] = b; op = op + 1; s = s + 1
result: out[0 .. op]
```

A payload that fails in any of the three ways SHALL be treated as not received: the receiver delivers nothing from it and owes no Ack for it, so the sender resends the chunk [V223.LRA.LINK clause 9.4]. A decoder SHALL NOT read or write outside its buffers for any input.

NOTE: An empty compressed payload decodes to an empty result. Senders never produce one (clause 10); the reference implementation delivers it as an empty chunk.

## 10 The gain rule (the 8 byte rule)

For a chunk of n bytes (1 <= n <= 200) a sender with compression in force SHALL:

- send the chunk **plain** (flag LZ clear) if `n <= 8`, or if it has no compressed form of at most `n - 8` bytes;
- otherwise MAY send a compressed form of at most `n - 8` bytes with flag LZ set (the reference encoder always does when it finds one).

A compressed payload SHALL decode, per clause 9, to exactly the n bytes of the chunk. A resend of a chunk SHOULD carry the same bytes as the first send (the reference encoder is deterministic, so it does).

NOTE: The 8 byte minimum keeps compression from costing airtime on chunks it barely shrinks, and keeps the rule simple for both ends to reason about.

## 11 The preset dictionary

The preset P is the 567 bytes of Annex A. Its SHA-256 is

`9881ACBB232CDB7DFF1EEDA7D41A4ED6006FBC1CEA40256AABDBA0B47E16A2CE`.

P is part of the air format. It SHALL NOT change under CAP_LZ: a different dictionary needs a new capability bit (V223.LRA, registration policy).

Its content, in order: ANSI SGR and cursor sequences (reset, clear screen, home, bright white on black and on blue, erase line, cursor positions, save and restore, cursor hide and show, the four cursor moves), the bold and normal forms of the eight foreground colours, the eight backgrounds, the plain eight foregrounds, CR LF CR LF, a run of 34 spaces, runs of CP437 single and double horizontal lines, single and double box corners and joints, runs of the CP437 full, light, medium, dark, lower half and upper half block characters, the same blocks and lines in UTF-8, and the words `Press any key (Y/N)? `, `Enter your password: ` and `Welcome to `.

## 12 Encoding (informative)

Any encoder that meets clauses 8 and 10 interoperates. The reference encoder, for information:

- It is greedy: at each input position it takes the longest match of at least 3 bytes (at most 34, and not past the end of the input) within the last 1024 bytes of the virtual buffer; where none exists the byte becomes a literal. Literals between matches go out as runs of up to 128.
- It finds candidates with hash chains over 3 byte groups: 256 buckets, bucket `((a OR b << 8 OR c << 16) * 0x9E3779B1 mod 2^32) >> 24`, the chain for P built in advance, at most 64 candidates per position, nearest first. On equal lengths the first candidate found (the nearest) wins.
- It gives up as soon as its output would exceed `n - 8` bytes.

The vectors marked "reference encoder output" in Annex B come from this encoder. Another encoder may produce different, equally valid bytes.

## 13 Conformance

- A station that ever offers CAP_LZ SHALL implement clause 9 exactly and SHALL pass every decoding vector of Annex B.
- A station that sends compressed payloads SHALL meet clause 10; its output SHALL decode per clause 9. Matching the reference encoder's bytes is not required.
- A conformance claim SHALL state the revision of this part.

## Annex C (informative): Rationale

- **Per frame, no history.** Clauses 7 to 13 keep each frame independent so ARQ can resend or reorder it. A shared window at that layer would desynchronise the two ends. Clause 14 puts the window above ARQ instead: a resent frame is the same compressed bytes, and the decoder moves only on the in order stream.
- **A preset made of screens.** Most of what a BBS sends is escape sequences and box art; a preset of exactly that lets even a short frame find long matches.
- **A tiny format.** Two token kinds, no entropy coding: a decoder fits in a few dozen lines of code and a few hundred bytes of RAM on the modem's microcontroller.
- **Distances of 1024.** P (567) plus the largest chunk (200) is 767, so 10 bits of distance reach every byte of the virtual buffer.

## 14 Stream compression (CAP_LZ_STREAM)

This clause applies only when stream compression is in force (clause 6). It does not change clauses 7 to 13, which remain the rule for a peer that agreed to CAP_LZ and not to CAP_LZ_STREAM.

The sender compresses the user byte stream with LZ77 over a 1024 byte history before the stream is split into ARQ chunks. The history starts as the preset of Annex A. ARQ carries the compressed bytes. A retransmission SHALL be the same bytes as the first transmission of that chunk. The receiver decodes only the bytes ARQ delivers in order. Data frames of a stream compressed call SHALL NOT carry flag LZ.

Tokens are the per frame tokens of clause 8, with two changes. A literal run is at most 127 bytes (first byte `0x00` to `0x7E`). The byte `0x7F` is not a literal run: it is RESET, and both the encoder that emitted it and the decoder that reads it SHALL load the preset into the history again. A match is unchanged (first byte `0x80` to `0xFF`, then one distance byte).

The sender SHALL emit RESET after the compressed bytes already queued, and then clear its history, when the link retrains or enters resync. On link loss both sides SHALL clear their histories. Clearing on loss may wait, on the receiver, until every compressed byte already held by ARQ has been decoded.

The reference encoder keeps the history, the hash chains and a small output hold in fixed arrays and does not allocate. Chain positions are 16 bits. The encoder SHALL emit RESET on its own before those positions would wrap.
